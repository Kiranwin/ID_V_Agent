# 帧特征缓存问题修复报告

## 结论

本次改动已覆盖提出的三个问题：训练前向的梯度安全、评估/诊断抽样命中率、以及跨任务缓存键正确性。

## 问题与修复

### 1. 训练循环未使用 `frame_cache`

根因是持久缓存保存的是 `feature.detach().cpu()`；若训练跨 step 复用，会切断视觉投影和条件投影的 autograd 图，因此不能直接把评估缓存接入训练。

修复位于 `idv_agent/scripts/train_vla.py`：

- `encode_batch()` 新增 batch 内缓存 `batch_frame_cache`。
- 同一 batch 内重复的 `(instruction, mode_id, path)` 直接复用图连接张量，梯度会按重复使用次数累加。
- 持久 `frame_cache` 仍只在 `eval()` + `torch.no_grad()` 路径使用。
- `forward_loss()` 保留缓存参数透传，但训练循环不传持久缓存，并在 docstring 中明确设计约束。

### 2. 默认评估/诊断抽样命中率接近 0

根因是均匀抽样破坏了 stride=3 滑窗的相邻性。

修复内容：

- 新增 `_contiguous_subset()`，按 episode 连续运行选择样本，尽量保留相邻历史帧重叠。
- `evaluate_vla.py` 和 `diagnose_act.py` 改用连续抽样。
- 评估默认 `--max-samples` 从 16 调整为 256；诊断默认保持 256，但明确其为连续样本数。
- 评估、诊断及训练验证结果均输出 `hits`、`misses`、`encoded`、`unique_frames_encoded`、`hit_rate`，便于实测验证缓存效果。

### 3. Cache key 缺少 instruction/mode

修复后持久缓存键统一为：

```text
(instruction, mode_id, path)
```

batch 级 `cache_by_task` 也使用 `(instruction, mode_id)`，与帧缓存口径一致。同一路径在不同任务指令或模式下不会静默复用错误特征；pad 槽不写入持久缓存，也不计入命中/编码统计。

## 回归测试

新增 `tests/test_frame_cache_behavior.py`，覆盖：

1. batch 内重复帧只编码一次且梯度仍可回传；
2. 不同 instruction 的相同路径生成不同缓存键并分别编码；
3. 连续抽样保持记录相邻。

验证结果：

- 新增测试 + 训练继承测试：`7 passed`
- `python -m idv_agent.scripts.smoke_test`：通过
- `python -m compileall -q idv_agent`：通过
- 全量 pytest：`58 passed, 1 failed`；唯一失败为既存配置测试 `test_subgoal_v1_aligns_all_vla_intents`，与本次缓存/抽样改动无关。
