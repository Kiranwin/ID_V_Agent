# 03 · 数据格式与动作空间

> 全链路唯一数据约定。schema 改动必须先过这里，再动 `idv_agent/configs/schema.py`。

## 1. 动作空间（20 离散 + 4 连续）

离散类别 `ActionCategory`（见 `configs/schema.py`）：

| id | 名称 | 说明 |
|---|---|---|
| 0 | NOOP | 无操作 |
| 1 | MOVE | 移动（无视角转动） |
| 2 | LOOK | 转视角 |
| 3 | MOVE_LOOK | 边移动边转视角 |
| 4 | INTERACT_TAP | 交互·短按（开始破译/救人/开箱） |
| 5 | INTERACT_HOLD | 交互·长按（破译中） |
| 6 | INTERACT_RELEASE | 交互·松开 |
| 7 | VAULT | 翻窗/翻板（Space） |
| 8 | DROP_BOARD | 占位类，需视觉判定区分（P10，语义并入 VAULT） |
| 9-10 | SKILL_1_TAP / SKILL_1_HOLD | 技能 1 |
| 11-12 | SKILL_2_TAP / SKILL_2_HOLD | 技能 2（当前律师默认未绑定） |
| 13-16 | ITEM_1..4 | 道具栏 |
| 17 | MAP | 查看地图 Tab |
| 18 | EMOTE | 表情 |
| 19 | OTHER | 其它 |

4 连续通道：

| idx | 名称 | 范围 | 语义 |
|---|---|---|---|
| 0 | move_x | [-1,1] | A=-1 / D=+1 |
| 1 | move_y | [-1,1] | S=-1 / W=+1 |
| 2 | cam_dx | [-1,1] | 鼠标 X 增量 / `cam_pixel_scale` |
| 3 | cam_dy | [-1,1] | 鼠标 Y 增量 / `cam_pixel_scale` |

> **P7 灵敏度域**：`cam_pixel_scale` 是「像素增量 → 1.0」的物理尺度（默认 200 像素）。游戏内鼠标灵敏度不同 → 相同像素增量转角不同。**录数据时记录采集机的灵敏度**，训练与部署保持一致，否则动作「笨」（静默域偏移）。

## 2. VLA 原生动作块（当前主线）

VLA 不受上面的 20 类离散动作约束。模型直接读取连续画面序列、任务指令和
历史动作，预测短动作块；旧 `samples.jsonl`/`ActionCategory` 仅作为教师数据或最终
执行器适配，不是 VLA 的输入契约。

当前训练主线为 v5；v3/v4 仅保留用于历史数据兼容。任何新 ACT 训练只能消费
通过第 7 节「训练集准入审计」的 v5 数据与训练期 sidecar 标签。

固定 v5 形状：

每条样本顶层必须带 `mode`，并在任务文本前注入对应 token：`<mode:standard>`、
`<mode:joint_hunt>` 或 `<mode:blackjack>`。三种模式共享本动作空间；差异由模式
LoRA 学习，而不是复制三套动作头。

```text
observations.frames       v3 为 3 帧；v4/v5 为 3..8 帧（当前 v5 固定 8）
action_chunk              4 步
每步 duration_frames      v5 固定 6（约 0.2 秒@30 FPS）
```

每个动作块元素采用九方向移动、每轴五档相机桶和六个独立按键位：

```json
{
  "mode": "standard",
  "move_dir": 1,
  "camera_dx": -2,
  "camera_dy": 0,
  "buttons": [1, 0, 0, 0, 0, 0],
  "duration_frames": 6
}
```

`move_dir` 取值为 `0..8`：`stop/north/northeast/east/southeast/south/southwest/west/northwest`。
`camera_dx/camera_dy` 取值为 `-2..2` 五档。v5 每个动作块还必须保留
`camera_dx_px/camera_dy_px`，它们是该 6 帧宏动作的 Raw Input 净像素位移；校验器会
验证像素值与桶一致。桶边界和执行代表值只定义在 `idv_agent/vla/action_chunk.py`：
`[-12,12]→0`、`(12,67.5]→1`、`>67.5→2`（负方向对称），代表值为
`-2/-1/0/1/2 → -110/-25/0/25/110 px`。训练标签和 ACT 执行器共用这张表。
这是相邻执行代表值的中点划分：`0↔25` 的边界为 `12.5`（按整数 Raw Input
写为 12/13），`25↔110` 的边界为 `67.5`（按整数写为 67/68）。因此 `±13..±67`
属于细转 `±1`，而非粗转 `±2`。
`buttons` 顺序固定为
`interact/vault/item/heal/sprint/crouch`。其中 `interact` 是一次性 Q 触发脉冲：只有
包含 Q 按下边沿的宏步为 `1`，自动破译后续的 `INTERACT_HOLD` 状态不重复产生交互
按键；其余按键位保持 0/1 持续状态语义。ACT 执行器将 `interact=1` 发送为一次
`press + release`，不会把 Q 放入持续按键集合。

相机增量的聚合约定：`per_frame_actions.csv` 中的 `cam_dx_px/cam_dy_px` 是逐帧 Raw Input
像素增量，
构建一个 v5 宏动作（固定 6 帧）时必须先求有符号累积位移，再量化到五档；不能取帧均值，
否则正常的微调会被压回 `0` 桶。移动方向与相机桶是并行输出，执行器可以同时发送
（例如 `W + camera_dx=1`），从而表达“转视角改变后续行进朝向”；移动键本身仍保持
相机相对语义，不把它误解为世界坐标方向。若一个宏动作内发生左右反转，单个桶无法
表达中间序列，应缩短 `macro_frames` 或在后续版本引入子步动作。

v5 的 `observations.history_actions` 是最近 8 个已经完成的 6 帧宏动作摘要，而不是单帧
采样；其字段布局与 ACT 执行器的 72 维 history 完全一致。canonical v5 使用 24 帧
anchor 间隔（等于 4×6 帧未来标签窗口），确保所有未来帧都有且仅有一个默认标签窗口。
冷启动时在 8 个完整历史宏
动作形成前，history 固定为 8 个零动作；视觉窗口达到 8 帧后即可产生首个 v5 样本，
不因等待 history 而丢失开局早期交互标签。

这种设计覆盖对角移动，又避免把交互动作编码进导航类别。YOLO bbox、状态机和几何量
放在可选 `auxiliary`，模型在缺少这些字段时仍必须能够推理。
完整校验和构建实现位于 `idv_agent/vla/action_chunk.py` 与
`idv_agent/scripts/build_vla_chunks.py`，产物为 `vla_chunks.jsonl`。

快慢 VLA 的时序窗口、context 融合、特征缓存和慢标签采样协议见
[docs/15-快慢VLA接口与时序缓存协议.md](15-快慢VLA接口与时序缓存协议.md)。该协议将运行时
缓存上限固定为 8 帧；这里的 v3 `observations.frames` 历史字段是数据兼容字段，后续
构建器会增加 `slow_label` 与 `loss_mask`，不能由训练器临时推断。

### 2.1 帧-动作时间对齐协议（强制）

VLA 样本采用因果未来标签，禁止把“当前正在发生的动作”直接当作当前帧的
决策标签。`anchor_frame` 表示最后一张输入画面；动作块从
`anchor_frame + action_delay_frames + 1` 开始。这里 `action_delay_frames` 的语义是“观测结束
后跳过的帧数”，不是总帧间隔；默认值 1 表示跳过 `anchor+1`，首个动作帧为 `anchor+2`。
这样至少隔开一帧（约 33ms@30FPS），避免捕获、推理和写盘延迟造成标签泄漏。

```text
输入帧:       t-6, t-3, t       （观测结束 = t）
延迟保护:                         t+1
动作块标签:                         t+2 ... t+25
```

录制时所有帧和输入事件必须使用同一 `perf_counter_ns` 时钟。构建器优先使用
`frame_timestamps.csv`，再将事件按时间窗口聚合到未来动作块；不得仅凭文件名或
线性帧号假定同步。若采集/推理延迟改变，应重新测量并调整 `action_delay_frames`，
同时在 `alignment` 字段记录实际值。

### 2.2 VLA v3 意图列表（任务级）

意图是短时任务约束，不是每帧按键类别；每条样本可只标一个主意图：

| 意图 | 含义 |
|---|---|
| `search_cipher` | 搜索尚未锁定的密码机 |
| `align_cipher` | 调整视角/位置让目标进入可接近方向 |
| `approach_cipher` | 向目标持续靠近 |
| `start_decode` | 已出现交互提示，准备按 Q |
| `decode` | 保持破译，包含校准等待 |
| `recover_target` | 目标暂时丢失，重新观察/搜索 |
| `avoid_obstacle` | 遇障碍进行短时绕行或脱困 |
| `stop_safety` | 不确定、异常或等待人工确认 |

意图字段只表达“当前要完成什么”，动作块字段表达“接下来怎么做”；二者不互相
替代。第一阶段优先覆盖 `decipher`、`travel`、`rotate`、`idle`，其余意图通过专项
录制逐步补齐。

### 2.3 对外部建议的选择性合并

已参考 `keymap.json`、`actions.md`、`intents.md`，但没有直接复制文件或实现。最终取舍：

| 建议 | 决策 | 原因 |
|---|---|---|
| WASD 合成八方向移动 | 采用，连同 `stop` 组成九方向 | 对角移动不能用左右/前进均值替代，否则标签含义会模糊 |
| 相机每轴离散桶 | 采用五档 `-2..2` | 第一版更容易学习、推理更快；原始鼠标增量留在辅助字段以便重分桶 |
| 六个开关键位 | 采用 `interact/vault/item/heal/sprint/crouch` | 低频键先不进主头，但原始事件始终保留，后续可扩展 |
| 八个顶层意图 | 采用 `decipher/kite/rescue/rotate/travel/search/gate/idle` | 意图表达任务阶段，子意图不强制注入，降低标注成本 |
| 固定键位映射 | 仅作为默认参考 | 必须以当前游戏内实际键位和角色配置为准；尤其 F 键语义不能盲目覆盖 |
| 每帧即时动作标签 | 不采用 | 改用因果未来动作块，并记录真实时间戳和延迟 |

因此，VLA 主头不输出自然语言动作字符串，也不依赖旧 20 类 `ActionCategory`；最终
执行器再把九方向和按键位映射为实际键鼠事件。老师建议中的低频键会保留在原始
`events.csv`，而不是丢弃，以便未来扩展动作头。

## 4. 意图体系（16 维严格正交原型）

10 类意图 `IntentCategory`（见 `configs/intent.py`）：

| id | 名称 | 说明 |
|---|---|---|
| 0 | IDLE | 待机观察 |
| 1 | MOVE | 移动巡逻 |
| 2 | DECODE | 破译密码机 |
| 3 | VAULT | 翻窗/翻板 |
| 4 | HEAL | 自我/队友治疗（**依赖视觉，弱监督，启发式推断不含**） |
| 5 | RESCUE | 救援队友（**依赖视觉，弱监督**） |
| 6 | USE_SKILL | 使用技能 |
| 7 | USE_ITEM | 使用道具 |
| 8 | EMOTE | 表情/呼救 |
| 9 | OBSERVE | 查看地图 |

原型向量用 QR 分解保证严格正交（`np.random.randn` normalize 不严格正交，会污染快系统条件输入的语义）。固定 seed 跨会话可复现。

> **P5 警示**：HEAL / RESCUE 依赖视觉判定，按键推断的启发式映射不产生这两个标签。慢层部署时想输出「去救人」但未见过该标签 → 意图空间天生残缺。新项目保留此清醒标注，后续用视觉辅助标注补。

当前律师键位：`E` 登记为治疗键（`keymap.heal`）。治疗暂不进入首要“找机→破译”训练目标，后续结合画面/场景补充语义标签。

### 鼠标轨迹回放（调试）

可用 `replay_mouse` 检查 raw session 的鼠标轨迹：

```powershell
# 只统计轨迹，不发送输入（默认）
python -m idv_agent.scripts.replay_mouse data/vla_raw_sessions/<session_id>

# 实际按原始时间间隔回放相对位移
python -m idv_agent.scripts.replay_mouse data/vla_raw_sessions/<session_id> --send-input --start-delay 5
```

回放器读取 `mouse_deltas.csv` 的相对位移，再通过 `pydirectinput` 发送；`--scale` 可缩放位移。默认 dry-run，`--send-input` 仅限
官方自定义剧本/训练营，且应先确认游戏窗口已获得焦点。

### Raw Input 鼠标诊断

由于游戏可能锁定系统光标，正式替换采集后端前先运行诊断命令：

```powershell
python -m idv_agent.scripts.diagnose_raw_mouse --duration 10 --output data/raw_mouse_diagnostic.csv
```

运行期间只在官方自定义剧本/训练营中移动视角。命令通过 Windows 用户态 Raw Input
读取相对位移，不发送输入、不读取游戏内存。重点观察输出中的 `nonzero_rate`、
`max_abs_dx/max_abs_dy` 和累计位移；确认存在稳定非零数据后，才能把该后端接入正式
`record_vla` 与逐帧动作提取。

## 6. 破译状态机语义（P2 修复点）

第五人格按一次 Q 即自动破译（无后续按键），需要隐式状态识别（`labels/state_machine.py`）：

1. Q press（always-enter）：进入破译态，重置起始时间。
2. WASD / SKILL / ITEM / MAP / EMOTE press：退出破译（做别的去了）。
3. **Space press during decode = 校准**（不是真翻窗）。新项目在 `FrameState` 增加 `decode_calibration` 标记帧——`cat = INTERACT_HOLD` 但 `flag = calibration`，供后续视觉辅助标注校准样本（补救 P2，不必重录即可能学到校准）。
4. 破译 > `max_decode_duration_s`（90s 默认）：强制退出（Q 误触保护）。
5. 破译中 NOOP/LOOK/VAULT 帧重写为 INTERACT_HOLD（语义 = 破译中）。该状态只用于
   识别持续破译，不等价于再次按 Q；逐帧提取同时写出 `decode_start` 边沿字段，v5
   宏动作只把该边沿聚合为一次 `buttons[0]` 脉冲。

## 7. v5 MVP 数据准备与标签契约（当前唯一主线）

本节是从采集到可训练数据的唯一顺序。`data/new_vla_raw_sessions` 是只读原始
证据；所有 JSONL、CSV、标注池和审计报告都是可重建派生物。不得以手改
`per_frame_actions.csv` 或覆盖 raw 文件的方式修标签。

```text
官方自定义剧本 / 训练营的人类演示
  │ record_vla（frames + 同一 perf_counter_ns 时钟的 events / Raw Input mouse）
  ▼
validate_vla_raw
  ▼
人工 intent_segments（只标顶层时间片段） + frame_states（按需）
  ▼
extract_session（逐帧按键状态 + cam_dx_px/cam_dy_px + decode_start）
  ▼
build_vla_chunks / train_vla_chunks_v5（8 帧观测 → 因果未来 4×6 帧 chunk）
  ▼
prepare_mvp_data --event-centered（整 session train/val；Q 样本替换重叠 periodic 样本）
  ├─ ACT 主标签：slow_label + action_chunk[0..3]
  ├─ grounding sidecar：画面中密码机/Q 提示的事实
  └─ camera-control sidecar：人在该画面下的意图性镜头决策
  ▼
audit_mvp_training_data（训练集准入） → train_vla
```

### 7.1 原始采集与逐帧行为标签

每一个原始 session 必须有：

```text
frames/                    连续帧，文件名从 00000000.jpg 连续递增
frame_timestamps.csv       每帧 capture 的 perf_counter_ns
events.csv                 键盘/鼠标 down/up 事件，同一时钟
mouse_deltas.csv           Raw Input 相对 dx/dy，同一时钟
meta.json                  mode、任务、FPS、录制范围、action_delay_frames=1
```

`record_vla` 只采集，绝不注入输入；先运行：

```powershell
python -m idv_agent.scripts.validate_vla_raw <session>
```

`extract_session` 对每个保存帧的时间区间 `(prev_frame_ts, frame_ts]` 回放输入：

| `per_frame_actions.csv` 字段 | 唯一来源 | 作用 |
|---|---|---|
| `move_x/move_y`、`held_keys` | events.csv 的按住状态 | 宏动作移动和按键标签 |
| `cam_dx_px/cam_dy_px` | mouse_deltas.csv 的区间有符号和 | v5 相机标签的唯一物理来源 |
| `cam_dx/cam_dy` | 像素值除以旧 `cam_pixel_scale` | 仅历史 v3/v4 兼容；v5 不使用它分桶 |
| `decode_start` | Q 按下边沿 + DecodeStateTracker | v5 `buttons[0]` 的一次性 Q 脉冲 |
| `decode_calibration` | 破译中 Space | 状态/标注辅助；不是重复 Q |

录制开始后的“看图上似乎该转、但人尚未输入”的空白帧仍如实保留为 `replay=0`；
它不能被伪改成转向标签。若它不应成为决策训练样本，应由 chunk 选择/质量规则排除，
而不是篡改 Raw Input 行为证据。

### 7.2 人工慢标签与 v5 因果 action chunk

人工只编辑 `intent_segments.csv/jsonl` 的连续区间：

```text
start_frame, end_frame, intent, segment_id
```

MVP 保留 `travel` 和 `decipher`；`subgoal` 由固定 `subgoal.v1` 规则派生，不能作为
第二套人工动作标签。v5 chunk 的固定协议为：

| 项目 | 约定 |
|---|---|
| 视觉观测 | 8 帧，帧距 3；最后一帧是 `observation_end_frame` |
| action delay | 1 帧；h0 从 `observation_end_frame + 2` 开始 |
| 行为目标 | 4 个连续宏动作，每步固定 6 帧；部署/训练因果执行只消费 h0 |
| 周期采样 | anchor stride 24，避免相邻 periodic 样本的未来窗口重叠 |
| Q 事件 | event-centered anchor=`q_frame-2`，h0 从 Q 帧开始；同未来窗 periodic 行删除 |
| Q 决策慢标签 | event-centered 行的顶层 `slow_label` 取 Q 决策帧的 `decipher/start_decoding`，观测历史帧仍保留真实历史语义 |

`train_vla_chunks_v5` 会逐记录验证时间顺序、帧覆盖、8 帧/8 history、每步 6 帧、
像素净位移与 bucket 一致性，并写 `vla_chunks_v5.audit.json`。单 session audit 通过
不等于可训练；还必须通过第 7.5 节的全数据准入审计。

### 7.3 标签层 1：行为复刻标签（永不人工覆盖）

v5 `action_chunk[h]` 是人类演示在未来 6 帧实际执行的复刻标签：

```text
move_dir, camera_dx/camera_dy, camera_dx_px/camera_dy_px,
buttons[interact/vault/item/heal/sprint/crouch], duration_frames=6
```

相机必须先对 6 帧 Raw Input 求有符号净位移、后分桶：

| 净像素范围 | bucket | 执行器代表像素 |
|---|---:|---:|
| `[-12, 12]` | `0` | `0` |
| `[-67.5, -13]` | `-1` | `-25` |
| `<= -68` | `-2` | `-110` |
| `[13, 67.5]` | `+1` | `+25` |
| `>= 68` | `+2` | `+110` |

边界与执行代表值只来自 `idv_agent/vla/action_chunk.py` 的
`CAMERA_BUCKET_EDGES_PX` / `CAMERA_BUCKET_COMMAND_PX`；训练、离线评估和执行器
不得各自维护另一套阈值。`replay_camera_dx/dy` 是对 h0 行为标签的审计副本，
不是 `desired_turn_*` 的替代物。

### 7.4 标签层 2：训练期视觉事实（grounding sidecar）

`data/mvp_act_grounding_pool_v1/act_grounding_annotations.jsonl` 的每行对应原始帧，
来自三个 YOLO 类 `cipher_visible/cipher_highlight/interact_prompt`。它不是 runtime
检测依赖，也不要求每一行都恰好是 ACT decision endpoint；Dataset 只会精确匹配
`(session, observation_end_frame)` 的行，其余 Q 邻域帧保留为标注覆盖证据。

| 字段 | 语义与不变量 |
|---|---|
| `cipher_bbox_xyxy_norm` | 可见密码机（优先）或高亮的 `[x1,y1,x2,y2]`；无机器为 `null` |
| `target_side` | `left/center/right/none`；无 bbox 必须为 `none` |
| `interact_prompt` | Q 交互 UI 是否出现；为 1 时密码机一定可见 |
| `cipher_reachable` | 当前可接近/交互；prompt=1 时必须为 1 |

角色遮挡密码机但仍出现 Q 提示时，仍标记密码机可见；`target_side` 以
`interact_prompt` 框中心为准。没有标注不等于负样本：Dataset 将其 `grounding_mask=0`。

### 7.5 标签层 3：训练期镜头控制语义（camera-control sidecar）

这层解决“画面相近但 replay mouse 不同”的路径/避障混杂。文件为：

```text
camera_control_train.v2.rebucket675.annotated.jsonl
camera_control_val.v2.rebucket675.annotated.jsonl
```

每行必须精确匹配一个 canonical v5 的 `(session, observation_end_frame)`，并保存但不
修改 h0 `replay_camera_dx/dy`。人工填写的是：

| 字段 | 枚举 | 含义 |
|---|---|---|
| `camera_control_phase` | `search/target_acquire/target_align/hold` | 当前在扫视、首次获取、对齐、还是保持 |
| `camera_target_id` | `target_cipher/other_visible/none` | 画面内可见对象是否为导航目标 |
| `camera_steering_mode` | `target_center/path_follow/search_sweep/hold` | 镜头服务于中心化、绕行路线、扫视或停止 |
| `path_strategy` | `direct/detour_left/detour_right/unknown` | 仅 `path_follow` 可填前三项；其他必须 `unknown` |
| `desired_turn_dx/dy` | `-2..2` | 在当前视觉与路径状态下应执行的单步镜头意图 |
| `replay_camera_dx/dy` | `-2..2` | immutable 的 h0 行为复刻证据 |

`desired_turn_*` 可以等于 replay（大量直行搜索/获取确实如此），但绕障、保持路线、
录制延迟或无输入空白时可以不同。它不是“把机器拉到屏幕中心”的固定规则，而是人工对
当前阶段和路线的可执行判断。部署只使用模型预测的 control logits；绝不读取 sidecar。

标注文件必须先通过：

```powershell
python -m idv_agent.scripts.prepare_camera_control_annotations validate --input <file>
```

### 7.6 canonical MVP 数据与训练准入

当前唯一 MVP 训练根目录：

```text
data/mvp_vla_v5_event_centered_decision_label_v3_rebucket675/
  train/  732 chunks, 79 sessions
  val/    182 chunks, 20 sessions
  manifest.json
  class_balance_h0_rebucket675.json
```

它从 `data/new_vla_raw_sessions` 的 99 个 session 派生，按整个 session 划分、零重叠；
仅保留 `travel/decipher`。每次训练前运行：

```powershell
python -m idv_agent.scripts.audit_mvp_training_data `
  --dataset data/mvp_vla_v5_event_centered_decision_label_v3_rebucket675 `
  --grounding-annotations data/mvp_act_grounding_pool_v1/act_grounding_annotations.jsonl `
  --camera-control-train data/mvp_act_grounding_pool_v1/camera_control_train.v2.rebucket675.annotated.jsonl `
  --camera-control-val data/mvp_act_grounding_pool_v1/camera_control_val.v2.rebucket675.annotated.jsonl `
  --class-balance data/mvp_vla_v5_event_centered_decision_label_v3_rebucket675/class_balance_h0_rebucket675.json `
  --output reports/mvp_v5_rebucket675_training_data_audit.json
```

准入审计 fail-closed 验证：v5 schema/时间对齐、train/val session 零重叠、grounding
标注属于正确 split、control 标注属于正确 split 且精确附着到 decision endpoint、
control 的 replay 与 canonical h0 bucket 一致、以及 class weight 的统计范围确为 h0
训练标签。若 raw session 有重新采集或重建，再加 `--validate-raw-sessions`。
