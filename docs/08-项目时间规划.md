# 08 · 项目时间规划

> 目的：把 `docs/06-里程碑.md` 的总览展开成**以周为单位的可执行执行表**。
> 假设投入：**个人项目，每周约 8 小时**（晚间/周末）。若全职投入，各阶段工期约减半。
> 起点 t0 = 现有代码框架建成日（训练/真机均未跑）。里程碑验收式推进：不通过本阶段验收不进入下阶段。

---

## 0. 总览（相对起点 t0，按周）

```
阶段  周次       周期    里程碑      一句话
A     1 - 2      2 周    M0          环境打通：能录、能注入、延迟达标
B     3 - 6      4 周    M1          规则闭环：能打完整一局 + 评估基线
C     7 - 14     8 周    M2          数据管道 + 学习快层（BC）
D     15 - 22    8 周    M3          VLA 快层（3B 微调）+ 慢层 VLM 记忆
E     23+        持续    M4          双 agent / 多角色 / 评估完善
─────────────────────────────────────────────────────────────
关键路径：A → B → C → D（逐段验收，环环相扣）
真实总工期估算：约 5.5 - 6 个月（个人每周 8h 前提下）
```

---

## 1. 阶段 A · M0 环境打通（周 1-2）

**目标**：可捕获-注入闭环 Demo，延迟预算达标。

| 周 | 任务 | 验收 |
|---|---|---|
| 1 | 安装 PC 互通版；配置自定义剧本（3 Bot 队友 + 1 Bot 监管者）；导出键位表；核对 `configs/keymap.py` | 剧本可稳定开局，键位表齐全 |
| 1 | DDA 捕获工具：帧缓冲 + 下采样 + 发布（`capture/screen_capture.py`） | 60fps 稳定，实测延迟 ≤33ms |
| 2 | SendInput 注入全键位封装 + 时间戳日志（`capture/input_logger.py` + `agent/action_executor.py`） | 沙盒内角色可完整操作 |
| 2 | 画面流水线 + 延迟测量报告 | 捕获 ≤33ms、注入 <10ms、往返链路 ≤150ms |

**⭐ A 出口验收**：分层实时性假设成立 → 进 B。**A 若不达标，其余一切免谈**。

---

## 2. 阶段 B · M1 规则闭环（周 3-6）

**目标**：律师版规则 agent 能打完整一局，产出评估基线。

| 周 | 任务 | 验收 |
|---|---|---|
| 3 | 感知层起步：目标检测占位（模板匹配→后续小模型）+ HUD OCR（修机进度/技能CD/校准） | HUD 区域定位、检测脚手架可用 |
| 4 | 破译状态机 + 动作提取跑真实录像（`labels/extract.py`、`state_machine.py`） | 真实 session → per_frame_actions 正确 |
| 5 | 律师版规则 agent（`agent/rule_agent.py`：找→走→破译 + 转点威胁处理）闭环 | 沙盒内连续操作，非卡死 |
| 6 | 完整一局录像 + 评估基线（存活率/修机进度/被击倒次数/逃生率） | 有可对比的人类基线参照 |

**⭐ B 出口验收**：能打完整一局、有基线 → 进 C。

---

## 3. 阶段 C · M2 数据管道 + 学习快层（周 7-14）

**目标**：数据管道稳定 + BC 小策略网络，游戏内可验证。

| 周 | 任务 | 验收 |
|---|---|---|
| 7-8 | **数据闭环**（最高优先）：持续自采 + 人工接管重权（AI 模式/人类接管双录）；采集 10-30 局 | 覆盖 20 类动作，类别分布可控（P4） |
| 9 | bc_fast / bc_slow 真实数据单 epoch 验证（P3）；FP16 + GradScaler 稳定性 | 链路可跑、耗时实测 |
| 10 | **快层 chunk 化增量**：`FastController` 逐帧 → 按 chunk 输出（H=4~8，L1/flow）；数据标签重排 | dummy + 真实数据训练均通过 |
| 11 | **意图两级化增量**：解构 10 类 → 战术意图 + 动作意图；慢层 prompt 更新 | 慢层/快层条件输入正确 |
| 12-13 | BC 全量训练 + 快层升级，游戏内闭环验证 | 快层行为对比 M1 规则基线 |
| 14 | 慢层规划（LLM/VLM）+ 对局记忆（P11）接入 | 慢层输出可消费、事件触发重规划 |

**⭐ C 出口验收**：数据管道稳定、BC 快层在游戏内可验证 → 进 D。
**调节点**：若数据不够，回到 C 阶段重采（不强行进入 D）。

---

## 4. 阶段 D · M3 VLA 快层（周 15-22）

**目标**：3B VLA 微调（帧+状态→动作 chunk），慢层 VLM 规划，对比 M2。

| 周 | 任务 | 验收 |
|---|---|---|
| 15 | 租云 GPU（4090/A100）搭 VLA 微调环境；选型（Qwen 2B/3B + flow matching 头），对齐 3B+20-50Hz 基线 | 微调环境可用、选型定案 |
| 16-17 | 3B VLA 快层微调（连续损失；参考 GR00T VLM 截断 + LayerNorm、π0.5 梯度绝缘） | SFT 收敛、local 推理延迟实测 |
| 18-19 | 快层 VLA 在游戏内闭环 + 延迟/质量调优（CUDA graph、量化、异步 chunk） | 对比 M2 快层基线 |
| 20-21 | 慢层 VLM + 记忆增强完整接入；意图两级化在真实权重下验证 | 慢层可产出高层意图并驱动快层 |
| 22 | 对比评测（M2 vs M3） + 里程碑报告 | 明确 M3 ≥ M2 的证据 |

**⭐ D 出口验收**：VLA 驱动的完整 agent，对比 M2 有可量化提升 → 进 E。
**风险决策点**（见 `docs/04-环境与硬件`）：若本地 2080 Ti 推理延迟不达标，在 本地降频 / 云推理 / 快层保持小网络 VLA 只做慢层 三者间选定。

---

## 5. 阶段 E · M4 演进（周 23+，持续）

- 非对称双 agent 训练（AET）— 需多角色/自对弈条件成熟
- 多角色多地图泛化（角色/地图 embedding 或 LoRA 分域）
- **IDM 伪动作数据扩充**（绕开"必须同录按键日志"瓶颈）
- 评估体系完善 + 可选论文/开源

---

## 6. 关键路径与依赖

```
A(M0) ──验收──▶ B(M1) ──验收──▶ C(M2) ──验收──▶ D(M3) ──验收──▶ E(M4)
  环境打通        规则闭环          数据+BC            VLA           演进
```

- **不可并行跳过的**：A 未达标 → B 无法打真局；B 无基线 → C 无法对比验证；C 数据不稳 → D 的 VLA 无数据可微调。
- **可预研并行的**（不阻塞主线）：
  - 快层 chunk 化 / 意图两级化 的 **dummy 路径**可在 C 前预研（现在就能做，改 schema/model，dummy forward 验证）。
  - VLA 选型资料收集、云环境试跑，可在 C 阶段穿插。

## 7. 风险缓冲与里程碑硬门槛

| 关卡 | 硬门槛 | 未达标动作 |
|---|---|---|
| A 出口 | 延迟链路 ≤150ms | 不进入 B，先解决捕获/注入 |
| B 出口 | 能打完整一局 + 人类基线 | 不进入 C，先补规则/感知 |
| C 出口 | 数据管道稳定 + 快层可验证 | 回到 C 重采数据 |
| D 出口 | M3 ≥ M2 有证据 | 不盲目进 E，降级/回退方案 |

## 8. 里程碑交付物查对（对齐 docs/06）

- M0：可捕获-注入闭环 Demo + 延迟报告
- M1：沙盒完整对局录像 + 评估基线
- M2：数据管道 + 训练代码 + 快层升级
- M3：VLA 驱动完整 agent + 对比 M2
- M4：研究产出

**首个行动项（现在就能做）**：阶段 B 需要"真实数据"（打几局录像）。若当前无 Windows+游戏环境，先用 `smoke_test` + dummy 路径把「快层 chunk 化/意图两级化」的代码层预研做掉，不占真实工期。
