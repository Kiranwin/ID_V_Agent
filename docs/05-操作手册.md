# 05 · 操作手册

端到端实操：VLA 原始录制 → 校验 → action chunk 构建 → 标注/训练 → 部署。所有命令以项目根目录为当前目录。

## 0. 前提

- 管理员权限（NeAC 阻断非管理员 hook）。
- 依赖已装（见 docs/04）。
- 游戏窗口已开，自定义剧本已配置。

## 1. 录制

```bash
# 开始 VLA 原始录制（Ctrl+C 停止；或用 --max-seconds 自动停止）
python -m idv_agent.scripts.record_vla --window-title "第五人格" \
  --mode standard --max-seconds 60 \
  --output data/new_vla_raw_sessions
```

- 录制启动后立即采集；按 Ctrl+C 安全停止。别 Alt+Tab（窗口必须前台），关 OBS/浏览器视频保持稳定 fps。
- 每个 session 只录一个明确任务片段；优先覆盖“找机→靠近→扳手提示→Q→破译”。
- 打出的会话在 `data/new_vla_raw_sessions/<session_id>/`。

## 2. 校验并构建 VLA action chunks

先做 raw session 完整性检查：

```bash
python -m idv_agent.scripts.validate_vla_raw data/new_vla_raw_sessions/<session_id>
```

检查通过后构建 VLA action chunks：

```bash
# 从原始输入事件生成逐帧动作时间序列（VLA 预处理，不是旧 BC 标签）
python -m idv_agent.scripts.extract --session-dir data/new_vla_raw_sessions/<session_id>

# 生成 3 帧历史 → 4 步未来宏动作
python -m idv_agent.scripts.build_vla_chunks \
  data/new_vla_raw_sessions/<session_id> \
  --output data/new_vla_raw_sessions/<session_id>/vla_chunks.jsonl
```

产物是《docs/03-数据格式》定义的 `vla_chunks.jsonl`；旧 `samples.jsonl` 不再生成。

快慢 VLA 训练使用 v4 格式。人工只需在 session 根目录创建
`intent_segments.jsonl`，按连续片段标注 8 类顶层 intent：

```jsonl
{"segment_id":"seg_000","start_frame":0,"end_frame":89,"intent":"search"}
{"segment_id":"seg_001","start_frame":90,"end_frame":179,"intent":"decipher"}
```

合法 intent 为 `decipher/kite/rescue/rotate/travel/search/gate/idle`。subgoal 不人工标，
由 `subgoal.v1` 从 intent、帧状态和输入事件派生。完成片段标注后生成 v5：

```powershell
python -m idv_agent.scripts.build_vla_chunks `
  data/new_vla_raw_sessions/<session_id> `
  --schema-version vla.action_chunk.v5 `
  --history 8 `
  --slow-period-s 1.0 `
  --output data/new_vla_raw_sessions/<session_id>/vla_chunks_v5.jsonl
```

新 VLA session 的相机动作唯一来源是根目录的 `mouse_deltas.csv`（Raw Input
相对位移，列为 `timestamp_ns,dx,dy`）。构建器会在生成 chunks 前自动按帧时间戳
重新运行动作提取，写出/刷新 `per_frame_actions.csv`，再聚合相机桶；不要手工用
绝对坐标或旧的 `mouse_positions.csv` 生成相机标签。缺少 `mouse_deltas.csv` 的
session 会被拒绝，避免把绝对位置误当作相对位移。

v5 会在每个观测帧和 anchor 写入 `slow_label`，并按真实时间戳生成
`loss_mask.slow`；不能在训练 collator 中临时猜测这些字段。

创建 session 意图片段候选表（只生成少量候选边界，不自动决定最终意图）：

```powershell
python -m idv_agent.scripts.init_intent_segments `
  data/new_vla_raw_sessions/<session_id> `
  --output data/new_vla_raw_sessions/<session_id>/intent_segments.csv
```

打开 CSV 后只需填写/确认 `intent`，可选调整 `start_frame/end_frame`。意图要表达当前
阶段要完成的目标，不要因每次 LOOK/MOVE 就切段。完成后校验整段覆盖：

```powershell
python -m idv_agent.scripts.validate_intent_segments `
  data/new_vla_raw_sessions/<session_id>/intent_segments.csv `
  --frame-start 0 --frame-end <最后帧号> `
  --require-full-coverage
```

候选边界仅来自破译/交互等高置信动作阶段变化；它不是自动标注结果，必须人工确认。

### 2.1 自动生成 VG 帧状态和 QA

YOLO 框标注完成后，先从 raw session 事件流自动生成状态（默认不启用追击启发式）：

```powershell
python -m idv_agent.scripts.infer_frame_states `
  data/vg_cipher_20260901_105143 `
  --repo-root .
```

脚本会将无 JSON 的负样本视为无 `interact_prompt`，按 `Q+提示 → decoding`、活动输入
→ `walking`、无输入 → `idle` 推断，并在 `evidence` 中记录依据。抽查后如需修正，只改
`state`，不要删除 evidence。

完成 VG 转换后生成模板 QA：

```powershell
python -m idv_agent.scripts.generate_frame_qa `
  data/vg_cipher_20260901_105143 `
  --annotations data/vg_cipher_20260901_105143/vg_annotations.jsonl `
  --states data/vg_cipher_20260901_105143/frame_states.jsonl `
  --intent search
```

## 3. 密码机 YOLO 标注数据准备

按局划分 train/val，抽取帧并创建 YOLO 目录（不会自动伪造框）：

```bash
python -m idv_agent.scripts.prepare_yolo_dataset \
  --sessions 20260831_113220,20260831_131040,20260831_131904,20260831_132206 \
  --output data/yolo_cipher --stride 5
```

YOLO 类别固定为：`0=cipher_visible`（可见 3D 密码机）、`1=cipher_highlight`（墙后黄色高亮）、`2=interact_prompt`（扳手/Q 交互提示）。`decoding` 不再是 YOLO 类别，而是每帧一个状态枚举。

标注细则：

- `cipher_visible` 只框画面中实际可见的机器几何部分；被角色/墙体遮住的部分不要脑补补框。
- `cipher_highlight` 只框黄色高亮本体/天线，不框墙体和 HUD。
- `interact_prompt` 紧框扳手图标及其 `[Q]` 提示（如两者分离，合并成一个能覆盖二者的最小矩形）；这是允许发送 Q 的证据。
- `decoding` 在 `frame_states.jsonl` 中标注整帧状态；不画框。进入该状态后视为已按 Q，规则层禁止重复按 Q。
- HUD 被遮挡时只框实际可见区域；不确定是否为目标时留空，作为困难负样本。

使用 CVAT、LabelImg 或 Roboflow 打开 `data/yolo_cipher/images/*`，将框写入对应的 `labels/*/*.txt`；每行格式为 `class_id x_center y_center width height`，坐标归一化到 0～1。没有目标的帧保留空 txt。标注完成后先检查 `manifest.csv` 中 train/val 未混入同一局，再进入 YOLO 训练。

如果使用 X-AnyLabeling，JSON 会保存在图片旁边；软件不会为负样本生成空 JSON。一个 session 标注结束后，在项目根目录运行转换：

```powershell
python -m idv_agent.scripts.convert_anylabeling_to_yolo `
  data/vg_cipher_20260901_105143 `
  --split train
```

同名 JSON 转为 `labels/train/<image>.txt`；没有同名 JSON 的图片自动生成空 txt，并在终端显示 `missing_json_as_empty` 数量。先用 `--dry-run` 检查统计；默认拒绝覆盖已有非空 txt，确认重做时才加 `--overwrite`。源 JSON 不会删除。

## 5. VLA 训练

VLA 时序模型和训练 CLI 正在实现中。当前只准备数据，不使用旧的
`bc_fast`、`bc_slow`、`samples.jsonl` 或 `record.py` 链路。

### 5.1 Camera-control 语义标注

当 m26/m27 审计发现同一画面下 replay camera bucket 存在路径绕行歧义时，启动本地工作台的
独立标注页。它只允许编辑 camera-control v2 的意图语义；原始 replay、grounding、帧和待标注模板均只读。
保存会生成 `*.annotated.jsonl`，不会覆盖 `*.pending.jsonl`。

```powershell
python -m idv_agent.scripts.data_workbench `
  --root data/new_vla_raw_sessions `
  --camera-control-dir data/mvp_act_grounding_pool_v1
```

打开终端输出的 `http://127.0.0.1:8765/camera-control`。每条记录先看上下文和橙色
cipher bbox，再填写 phase、target、steering、path 及 desired dx/dy；`hold` 必须为
`(0, 0)`，仅 `path_follow` 可选择 `direct/detour_left/detour_right`。完成后再执行：

```powershell
python -m idv_agent.scripts.prepare_camera_control_annotations validate `
  --input data/mvp_act_grounding_pool_v1/camera_control_train.v2.annotated.jsonl
```

## 6. 部署（Agent）

### 6.1 实时运行（SGan）

`run_agent` 只保留 SGan（原 M29）；旧的 `--mode rule` 与 `--mode act` 已移除。
字段、依赖脚本、trace 结构与故障排查见 [agent.md](agent.md)。

```powershell
python -m idv_agent.scripts.run_agent --mode sgan `
  --checkpoint checkpoints/<run>/m29.pt `
  --model-path <Qwen3-VL-4B 权重目录> `
  --device cuda --duration 10 `
  --trace reports/sgan_dryrun.jsonl
```

默认 dry-run，只把决策写进 trace，不发送键鼠。真实发送仅限官方自定义剧本/训练
模式；当前 `deployable=false` 的 checkpoint 还需要显式加
`--send-input --allow-undeployed-send-input`。

### 6.2 原始录制

> VLA 训练数据使用独立的 `record_vla`。

```powershell
python -m idv_agent.scripts.record_vla `
  --window-title "第五人格" `
  --fps 30 `
  --max-seconds 60 `
  --output data/new_vla_raw_sessions
```

录制结束后先校验：

```powershell
python -m idv_agent.scripts.validate_vla_raw data/new_vla_raw_sessions/<session_id>
```

确认通过后进入 V6 标注与训练构建，流程见
[tools/data-workbench-v6.md](tools/data-workbench-v6.md)。
