# 17 · WK → VG → ACT 三阶段训练继承协议

本文冻结 WK → VG → ACT 的历史继承关系，同时明确当前 MVP ACT 的临时旁路和 m28
架构边界，避免把尚未可靠的 M2_VG 或旧 ACT checkpoint 误接入部署。

## 1. 唯一继承链

```text
Qwen3-VL base B0
  └─ WK LoRA → M1_WK = B0 + lora_wk
       └─ VG（冻结 lora_wk，训练 lora_vg/grounding）→ M2_VG
            └─ ACT（长期继承 M2_VG；当前临时旁路）→ M3_ACT
```

标准模式 M3_ACT 是共享底座；联合狩猎和黑杰克从 M3_ACT 继续，只添加各自 mode LoRA。

## 2. 阶段规则

- WK：从 B0 开始，只训练语言层 `lora_wk`，视觉塔冻结，输出 `M1_WK`。
- VG：必须从 M1_WK 加载，保留并冻结 `lora_wk`，训练视觉 grounding 投影/头，输出 `M2_VG`。`lora_vg` 作为后续容量扩展保留在协议中；当前实现和 manifest 不虚构该适配器。
- ACT：长期协议原本从 M2_VG 加载；因当前 M2_VG 已知问题，现行 MVP 协议从基础
  Qwen 初始化，禁止加载 M2，manifest 标记 `initialization=base_without_m2`。当前
  m28 ACT 训练的是 `StateDecisionExpert` 的 shared State Trunk、state heads 和
  Joint Planner；旧的 `slow_temporal`/`fast_temporal` 只保留兼容/诊断，不是部署的
  第二套动作决策器。checkpoint schema 为
  `m28_act.state_conditioned_joint_planner.v1`。

每个阶段都必须保存 `manifest.json`，记录 `stage`、`parent`、base model、adapters、冻结/可训练参数、数据版本和 schema 版本。统一协议实现于 `idv_agent/training/checkpoint_manifest.py`，可用 `python -m idv_agent.scripts.validate_checkpoint_manifest <checkpoint_dir>` 校验。

## 3. 合并与部署

实验阶段保留独立 adapter：`B0 + lora_wk + lora_vg + heads`。发布时可按顺序合并，但必须保留未合并备份。模式适配器为 `M3_ACT + lora_joint_hunt` 或 `M3_ACT + lora_blackjack`，卸载即回到标准 M3_ACT。

恢复继承链后，不能只把 `lora_wk` 文件放在目录中：ACT 的任务/指令 embedding 或多模态条件路径必须实际来自 M1_WK/M2_VG，并在 smoke test 中验证加载前后语义输出变化。当前 `base_without_m2` 临时协议不作该项声明。

## 4. WK 入口已实现

`idv_agent/scripts/train_wk_lora.py` 提供 M1_WK 的文本 SFT/LoRA 入口：

```powershell
python -m idv_agent.scripts.train_wk_lora `
  --data data/wk_vg/wk/wk_train.jsonl `
  --model-path C:/path/to/Qwen3-VL-4B-Instruct `
  --val-fraction 0 `
  --semantic-variants 2 `
  --output-dir checkpoints/M1_WK `
  --steps 500
```

它只接受 `reviewed/verified` 样本，使用 `<mode:...>` 条件 token，2080 Ti 上启用 FP16 +
GradScaler，并输出 `adapter/`、`processor/`、`manifest.json` 和 `metrics.json`。manifest
包含 `checkpoint.manifest.v1`、WK 文件 SHA-256、训练参数、统计信息和 artifact 路径。先用
`--dry-run` 检查数据格式。当前 WK 协议不保留独立验证集（`val_fraction=0`），70 条样本全部
训练；训练后运行 `python -m idv_agent.scripts.validate_wk_inference`，从训练集为每条样本生成
两个确定性语义变体，执行 EOS、重复率和答案字符 F1 gate。该 gate 只表示训练内语义一致性，
不能替代真正的留出泛化评估。

## 5. 当前实现与验证状态

三阶段入口和 manifest 校验已经落地；当前 MVP 的 ACT 解释如下：

- `train_wk_lora.py` 生成 `checkpoints/M1_WK`；
- `train_vg_grounding.py` 从 M1_WK 继承并生成 `checkpoints/M2_VG`；
- `train_vla.py` 当前禁止 `--init-checkpoint`，从基础 Qwen 初始化 m28
  `StateDecisionExpert`；训练/部署均使用预测 soft belief 进入 Joint Planner，生成
  m28 ACT checkpoint；
- `validate_checkpoint_manifest --require-artifacts` 已通过；
- `validate_wk_inference.py` 已加入训练内语义变体验收，统一使用 Qwen ChatML、左 padding 和
  显式 `<|im_end|>` 结束标记；
- 离线评估入口 `idv_agent/scripts/evaluate_vla.py` 已加入，强制校验 manifest 后只读取图片和 v4 标签，不发送任何输入；
- 重采样实现于 `train_vla.py --sampling stratified --seed <n>`：以完整 action chunk 为单位分为 `interact/move/other_key/stop` 四层（默认配额 35%/35%/15%/15%），层内按 episode 轮转，验证集保持原始分布，只改变训练索引不改标签。

**已验证的结论性认识**（来自多轮 500-step 规模实验，细节和逐次数据见 git log/历史 commit，不在本文重复）：

1. checkpoint 保存/恢复的 loss delta 为 0（FP16+GradScaler 下验证通过）；
2. M1_WK v3（500 steps，70 条全量训练）训练 loss 从 4.3766 降到 0.2027，140 条语义变体
   通过 gate：EOS 98.57%、平均重复率 3.97%、总体 F1 达标率 92.86%，standard/joint_hunt/
   blackjack 分别为 90.00%/100.00%/95.45%；
3. 训练内语义 gate 不能代表跨样本泛化；若需要发布级知识泛化结论，仍需另建独立留出集；
4. 不加权的动作分布训练会让移动头塌缩为多数类（`stop`/`north`），按键正例召回可能塌缩为 0；分层采样能显著提升按键召回，但不会自动修复移动方向的塌缩——需要单独的移动类别权重或分桶采样，且必须用训练集全局统计而非 batch 内频率，否则跨 batch 分布偏移会让权重失效；
5. 历史 slow intent 在共享编码器架构下准确率偏低，触发了分离时序编码器；随后
   m27 又暴露出 intent/control/action 并列、模块不协同。当前 m28 已改为 shared
   State–Decision Core，但尚未完成 GPU smoke、全量训练和 MVP 泛化验收，因此不能
   宣称已完成或部署。

当前没有可直接进入 dry-run/实机的 checkpoint；所有已完成的 500-step 候选均为诊断性实验，不代表可用模型。
