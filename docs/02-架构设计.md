> **历史说明**：本文包含早期 M1→M2 BC→M3 VLA 的渐进描述。当前分支已切换为
> VLA-only 主线；最新架构、数据状态和执行顺序以 [docs/00-当前状态.md](00-当前状态.md)、
> [docs/15-快慢VLA接口与时序缓存协议.md](15-快慢VLA接口与时序缓存协议.md) 为准。

> ID_V_Agent 总体架构：分层渐进式 VLA 化。本节是技术骨干，供实现 / 协作 / Review 参照。

## 0. 结论先行

1. **沙盒化是唯一可行战场**。网易对「辅助类脚本」零容忍，真人排位/匹配自动化无合规路径。战场锁定官方自定义剧本（Bot）+ 训练营。数据采集用 PC 单开自定义剧本（3 Bot 队友 + 1 Bot 监管者）。
2. **分层渐进式，不是一步到位**。端到端 VLA 对第五人格适配度低（无公开数据集、无 API）；对抗游戏 SOTA 全部是「状态特征 + RL + 自对弈」，个人不可及。现实路线：慢层 VLM 全局规划（秒级）+ 快层小策略网络（8-30Hz），VLA 作为快层二期演进。
3. **决策频率目标 8-12Hz 足够**。OpenAI Five 用 7.5Hz 打赢 Dota2 职业。第五人格对抗强度更低，端到端延迟预算 250-350ms 工程可达。
4. **VLA 无公开先例直接玩商业游戏**——真实空白，有研究增量价值。

## 2. 总体架构

```
┌─────────────────────────────────────────────────────┐
│ 慢决策层 (秒级, 异步)                                 │
│   VLM/LLM：全局策略 + 对局记忆 (agent/memory.py)       │
│   开局路线 / 转点时机 / 救人判断 / 密码机分配           │
│   输入：低帧率画面摘要 + 结构化状态 + 记忆               │
├─────────────────────────────────────────────────────┤
│ 快控制层 (8-30Hz)                                    │
│   M1 规则 agent → M2 小策略网络(BC) → M3 3B VLA        │
│   移动方向 / 视角 / 交互 / 技能 / 校准                  │
│   派发：Policy 抽象 (model/policy.py)                  │
├─────────────────────────────────────────────────────┤
│ 感知层 (10-30ms, 轻量结构化)                           │
│   帧采样 → 检测 / HUD 提取 / 事件检测(受击·挂椅·爆点)    │
├─────────────────────────────────────────────────────┤
│ 环境层                                               │
│   捕获: dxcam(DDA) + 输入日志(pynput)                 │
│   注入: pydirectinput(SendInput) — 默认 dry-run       │
│   沙盒: 官方自定义剧本 + Bot                            │
└─────────────────────────────────────────────────────┘
```

**分层原则**：感知只做轻量结构化；慢层异步执行（秒级，不阻塞实时链路）；快层对慢层指令做子目标分解。

## 3. 各层设计要点

### 3.1 环境层
- 仅 PC 互通版。DDA 捕获最低延迟（~16ms）、无模拟器指纹、键鼠是官方适配语义。
- 数据采集：PC 单开 + 自定义剧本（3 Bot 队友 + 1 Bot 监管者）。一局 6 分钟 × 20Hz ≈ 7000+ 帧。
- 明确不做：真人排位自动化、内存读取、进程注入、截帧 hook（DLL 注入是内核反作弊最高危行为）。

### 3.2 感知层
第五人格 AI 友好：第三视角 + HUD 固定布局 + 画面相对干净。感知**不逐帧跑大模型**：
- 帧采样：快层 20Hz，慢层 1Hz（异步）。
- 轻量检测：目标检测（YOLO 级，固定场景微调）输出密码机/椅/板窗 bbox。可先传统视觉起步。
- HUD 提取：OCR 修机进度、技能 CD、校准判定。位置固定，裁剪区域 OCR 极低成本。
- **事件总线**：受击/爆点/挂椅/破译完成/开门通电触发慢层重规划（否则慢层休眠省算力）。

### 3.3 慢决策层（秒级）
- 模型：开源 VLM（Qwen3-VL 系），本地可部署。
- 职责：开局路线、转点/换点时机、救人窗口、密码机分配、BP 角色选择。
- **记忆（P11 修复）**：对局内记忆（监管者最后位置、各机修机进度、地窖位置）+ 跨局经验。参照 Cradle 外部记忆结构。
- 输出：结构化指令（`{target, mode, priority}`）下发快层，不出按键。

### 3.4 快控制层（8-30Hz，VLA 落点）

按阶段演进：

| 阶段 | 实现 | 延迟 | 说明 |
|---|---|---|---|
| M1 | 规则 agent | <5ms | 子目标寻路 + 状态机，打通闭环 |
| M2 | 小策略网络(BC+RL) | 5-20ms | 输入检测结果+状态向量；行为克隆学人类分布避冷启动 |
| M3 | 3B VLA 微调 | 20-80ms | 帧+状态 token → action chunk。**模型的最终形态** |

- **动作空间（混合表征）**：离散语义动作（技能/交互/道具）+ 连续底层动作（移动方向、视角偏转）。纯离散 binning 高频控制会失败（FAST 论文动机），flow matching 连续表征 + 离散语义 token 是 π0 验证过的正解。
- **Policy 抽象**：M1/M2/M3 都实现 `Policy.decide(frame, state) -> Action`，上层调度零改动换实现（P9 落地）。
- **异步执行**：VLA 阶段预测 T 步 chunk，执行旧块时推理新块。
- **固定操作兜底**：QTE 校准、翻窗翻板走规则/缓存（Pokemon agent 导航器思路）。

### 3.5 延迟预算

```
捕获 DDA       16-33ms
感知(检测+OCR)  10-30ms
快层决策        5-20ms (M2) / 20-80ms (M3)
注入 SendInput  <10ms
硬件链路合计     ~50-100ms (M2) / ~100-150ms (M3)
慢层规划       异步，不占实时链路
端到端可玩预算  250-350ms
```

### 3.6 求生者首专项（已确认）

求生者比监管者更贴合 VLA 叙事（信息不对称，靠残缺视觉线索重建局势，是 VLM 长处）。

决策链（慢层职责）：
1. 开局：定位最近/最安全密码机 → 破译（QTE 走规则兑底）
2. 威胁评估：耳鸣/脚印/爆点时评估监管者方位 → 继续破译 or 转点
3. 转点：按地图拓扑选板窗/无敌点路线，向队友/已破译机靠拢
4. 救援：队友挂椅评估能救/不能救
5. 开门：大门通电后定位出口，防一刀斩

**信念管理**：维护监管者可能位置分布（事件驱动概率地图），慢层/快层公共输入。M2 后可换贝叶斯滤波。

**角色**：首发律师（已确认），破译型目标最直白。换角色只需换技能模块。

**评估**：存活率、单局修机进度贡献、被击倒次数/牵制时长、救援成功率、逃生率；对比同剧本人类基线。

## 4. 数据工程（项目命门）

1. 采集：PC 单开自定义剧本，DDA 录屏 + SendInput 日志 + 帧号对齐。
2. 标注：自动标注（画面事件 + 胜负结果），不需人工逐帧。
3. 人类数据：人类玩家打同一剧本采集操作分布（BC 初始化）。
4. 规模：M2 需万级帧-动作对；M3 VLA 需十万级。
5. 范围控制：先锁 1-2 个角色、1-2 张地图。

## 5. 训练路线

```
M1 规则闭环
  └→ M2a BC：自采数据 → 小策略网络
       └→ M2b 在线 RL：沙盒自对弈（reward: 淘汰数/破译进度/对局时长/技能命中）
            └→ M3 VLA化：3B 开源基座 → 帧+状态→动作 chunk，先 SFT 再在线 RL
                 └→ M4（远期）双 agent 非对称训练 + 多角色多地图泛化
```

**非对称（M4 才正视）**：self-play 因强度失衡失效，须 AET 双 agent 分训。M2/M3 对手是固定 Bot，天然回避。

## 7. 主要风险与缓解

| 风险 | 缓解 |
|---|---|
| 合规（自动化仍属「辅助脚本」灰色） | 只跑自定义剧本/训练营；不用内存/hook/截帧；小号测试；文档明确边界 |
| 检测（INJECTED 标志/行为分析） | 沙盒内无真人，压力低；输入加反应时抖动；不上规避检测工具 |
| 数据自采成本高 | 自动标注；先锁角色地图；万级即可启动 M2 |
| VLA 推理延迟 | 4090 级单卡 + 异步 chunk + CUDA graph；M3 用延迟实测选本地/云 |
| 泛化多角色地图 | M4 才处理，用 role/map embedding 或 LoRA 分域 |
