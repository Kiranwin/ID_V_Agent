> 当时的测试输出中；本文只保留动机、方案摘要和结论，不逐字保留原始报告的过程细节。

## 2026-09-01 · 帧特征缓存修复

**问题：**
1. 训练循环未使用 `frame_cache`：持久缓存保存的是 `detach().cpu()` 特征，若训练跨 step 复用会切断视觉投影和条件投影的 autograd 图。
2. 默认评估/诊断抽样命中率接近 0：均匀抽样破坏了滑窗的相邻性。
3. Cache key 缺少 instruction/mode：同一图片路径在不同任务下可能被静默复用错误特征。

**修复：**
- `encode_batch()` 新增 batch 内缓存，复用图连接张量，持久 `frame_cache` 只在 `eval()+no_grad()` 路径使用；
- 新增 `_contiguous_subset()`，评估/诊断改用按 episode 连续抽样；
- 持久缓存键统一为 `(instruction, mode_id, path)`。

**验证：** 新增 `tests/test_frame_cache_behavior.py`；全量 pytest 通过（1 项既存无关失败）。

## 2026-09-02 · 批量视觉与增量特征缓存

**目标：** 降低视觉塔重复编码成本。当时统计全部 `vla_chunks_v4.jsonl`：26,402 条样本引用 211,216 帧，唯一图片仅 27,305（重复率 87%），视觉塔前向理论可减少约 7.74 倍。

**方案：**
- `Qwen3VLBackboneAdapter` 新增批量视觉路径（`encode_frames` + micro-batch），`train_vla.py` 增加 `--vision-micro-batch-size`；
- 新增冻结 raw feature 增量缓存（`idv_agent/training/raw_feature_cache.py`）：只缓存 Qwen 视觉塔 pooling 后的 raw feature（`mean_dim1_v1`），训练时查表后重新执行可训练投影，不产生 stale feature 或梯度断开；
- 新增预编码脚本 `idv_agent/scripts/precompute_vla_features.py`，按 session 增量追加 shard。

**验证：** raw cache 与实时路径逐元素 `torch.equal` 一致；`tests/test_frame_cache_behavior.py` + `tests/test_train_vla_inheritance.py` 17 passed。

**已知限制：** `evaluate_vla.py` 独立 CLI 当时未接入 `--raw-feature-cache`（仍用旧 feature cache）；换模型/processor 需要新建缓存目录，不能混用旧 shard。

## 2026-09-03 · 分离时序编码器（消除梯度冲突）

**动机：** `SharedFastSlowVLA` 原架构中，慢头（intent/subgoal 离散分类）和快头（move/camera/buttons 连续控制）共享同一个 `SharedTemporalEncoder`（GRU），两个损失的梯度同时作用在共享参数上，方向不一致时相互干扰。实测验证集慢头意图准确率仅 16.41%，快头在不同采样策略下波动剧烈（非停止移动准确率 0%→61.89%），怀疑是共享编码器被快头优化主导。

**方案：** `idv_agent/model/fast_slow_vla.py` 的 `SharedFastSlowVLA` 拆分为独立的 `slow_temporal` 和 `fast_temporal` 两个 `SharedTemporalEncoder` 实例；`SlowVLAHead` 只消费 `slow_temporal` 输出，`FastVLAHead` 只消费 `fast_temporal` 输出。公开接口（`__init__`/`forward`/`initial_condition`/`condition_from_slow_output`）签名不变，调用方（`train_vla.py`、`act_policy.py`）无需修改。

**成本：** 额外参数约 1.18M（512-dim GRU × 2），相对 Qwen3-VL-4B + 视觉投影总量增加 <0.03%；GRU 前向 <2ms，推理延迟影响 <5%，仍满足 15 Hz 预算。

**只解决了一半：** 分离 GRU 消除了两个头对**同一份循环权重**的竞争，但 FiLM 条件融合（`context_embedding → FiLMConditioner`）发生在 slow/fast 分叉**之前**，是两者共用的输入路径。`train_vla.py` 当前训练用的两遍前向（第一遍 Slow 产出 `context_embedding`，第二遍用 `detach_slow_condition=False` 把它喂给 Fast）下，快头损失仍会经这条 FiLM 路径回传进 `slow_head`/`slow_temporal`——已用 `tests/test_two_pass_training_scheme_still_couples_fast_loss_into_slow_head` 实测确认（`slow_temporal`/`slow_head` 梯度非零）。这个耦合是有意保留的（否则快头学不到"如何使用慢头给出的上下文"），可通过 `detach_slow_condition=True` 关闭；另一个测试 `test_single_pass_gradient_flow_is_independent_when_condition_is_fixed` 确认了单次前向、条件为固定常量时两个 GRU 完全独立。

**验证：** `tests/test_separated_temporal.py`（4 项）覆盖参数独立性、输出形状、单次前向的梯度独立性、以及两遍训练下 FiLM 耦合的真实存在与可关闭性；已有 `test_act_policy.py`（5 项）与 `test_configs.py` 中 VLA 相关测试全部通过。

**破坏性影响：** 旧 checkpoint 字段 `core.temporal.*` 不兼容新的 `core.slow_temporal.*`/`core.fast_temporal.*`，`M3_ACT` 需要从 `M2_VG` 重新训练。

**后续验证项（未完成）：**
1. 用新架构重跑一次正式训练，对比慢头验证准确率是否从 16% 明显提升；
2. 若仍不收敛，尝试在第二遍前向显式传 `detach_slow_condition=True`（彻底切断 FiLM 耦合）做对照实验，判断残留耦合是否仍是主因；
3. 如果分离 GRU + 关闭 FiLM 耦合后依然不收敛，说明问题不止梯度冲突，需回到采样/数据质量排查。

## 2026-09-04 · VLA 数据校验 fail-closed

**问题：** raw 校验只覆盖了鼠标 CSV 的部分字段；动作构建对缺失、非法数值和缺失帧使用默认零值。坏标签因此会进入 v4 JSONL，表现为大量 stop/no-camera 样本并诱发模型坍塌。旧 audit 也没有逐条验证 v4 schema 或动作跨度。

**修复：**
- `validate_vla_raw.py` 统一校验三份 CSV 的表头、数值、时间顺序、帧文件 ID、meta 帧数/FPS/录制窗口；允许同时间戳 Raw Input 事件，但拒绝超出 `meta.end_ts_ns` 的事件；
- `build_vla_chunks.py` 要求 `per_frame_actions.csv` 覆盖全部帧、无重复、数值有限且时间戳与 frame timestamps 对齐，删除缺失动作补零路径；
- v4 alignment 增加必需的 `action_end_frame`；audit 逐条运行 schema 校验，检查动作跨度，并输出 move/camera/button/零动作分布；
- 新增 raw、chunk、audit 回归测试。

**现有数据扫描：** 100 个 raw session 全部通过增强校验。99 个现有 v4 文件共 7,501 条记录，schema 字段本身可解析，但全部是旧格式，缺少 `alignment.action_end_frame`，必须从 raw session 重新构建后才能进入新训练入口。当前动作分布仍严重偏斜：MVP train/val 的有效动作主要是 north/stop，多个方向为零，button 几乎只有 interact；这属于数据覆盖问题，不能由校验器自动修复。

**验证：** `python -m pytest -q --basetemp=tmp/pytest_temp`：132 passed, 1 skipped；`python -m idv_agent.scripts.smoke_test`：通过。

## 2026-09-04 · 分层活性测试定位 mean-pool 为画面信息瓶颈（C 档阶段一）

**问题复现：** 对同一批差异大画面（实测逐像素平均差 37~43/255），`probe_feature_activity.py` 分层抓特征显示：Qwen 视觉塔 **raw pooled**（`.mean(dim=1)` 后的单向量）画面间 cos 已 ≈0.999925（残差 ~2.5e-2 信号能量中只占 7.5e-5），视觉塔每帧上千 patch token 里含的东西/人/密码机位置信息在进入主干前就被整图平均抹平。随后 visual_projection 保留、FiLM/共享 GRU 再在该贫化输入上继续压缩，主踩塌点在 FiLM→GRU 段。

**证据（git log）：** mean-pool 自 `bc9315f`（"Add Qwen frame encoding"，2026-09-02 首次引入单帧视觉编码）起即存在；`codex/vla-action-chunks` 与 `vla-train` 两分支、缓存引入前后、共享/分离 GRU 前后，该 pooling 从未被修改。即**画面空间信息丢失是自引入帧编码就存在的架构级限制，不是某次回归**。

**为什么不做立刻修（取舍）：** 全量保留 patch token 会把单向量帧特征与下游 FiLM/GRU、`FrameFeatureCache`、train/checkpoint 契约全换成 token 序列，现存 M2_VG/M3_ACT 全部失效，需级联重训（M2_VG 的 1024→2560 投影契约也不可复用）。故采用**两阶段**：先只验"保留空间是否真有增益"，再决定是否破链重训。

**阶段一产出（本层诊断扩展）：**
- `idv_agent/model/spatial_grid_feature.py`：冻结视觉塔 per-token → 固定 **k×k 胞 average-pool**（保胞序位置，输出 `[N, k*k, D]`），不改现役 mean 链路，不持可训权重，CPU 可运行；产物连同 0 改动现役契约。
- `idv_agent/scripts/probe_spatial_vs_pooled.py`：同一 adapter 下对照现役 pooled vs k×k 保胞的画面可分性。
- `tests/test_spatial_grid_feature.py`：纯 CPU 几何/胞均值/非法网格/多 tile 反推单元测试。

**测量/结论：** 对 3 张差异大截图，画面可分残差从 pooled 基线 `7.5e-5` → k=4 `3.85e-3`（51x）→ k=8 `1.14e-2`（151x）；`cellmean`（去掉胞位置仍跨胞平均）回复到 0.999925，证明提升来自**保胞序的空间分量**本身，而非单纯维度或均化错误。k=8 展平确实显著拉开画面差异 → **支撑进入阶段二**（把 k×k 保胞 token 接到投影/时序，届时现役 M2_VG/M3_ACT 投影契约与 checkpoint 将按方案破坏并级联重训）。

**caveat（写入报告）：** 展平向量维度 k²×D 自身抬高画面可比性；结论以"保胞位置让 separable 信息进入主干"为据，最终是否对下游行为有增益，仍需阶段二接入投影/GRU 后用原分层活性探测在 GRU 输入端复测。

## 2026-09-04 · v5 采样去相关与训练图像增强

**动机：** 旧的连续 anchor 采样让相邻 chunk 高度重复，模型可以依赖上一动作和 history 的自相关取得较低 loss，削弱当前画面的边际贡献；训练阶段还可能通过固定画面统计建立捷径。

**方案：** v5 将相邻样本 anchor 间隔与观测窗口内部的历史帧间隔解耦：`anchor_stride=12`、`history_stride=3`、`history=8`，动作块仍为 4 步、每步 6 帧。标签不变，只改变 anchor 采样位置；部署与训练仍使用同源的像素相机桶/代表值表。训练 forward 对完整 history window 共享一组增强参数，加入 hue ±0.05、saturation/brightness/contrast 0.8～1.2 和平移 ±8 px；eval、raw session 与 v5 JSONL 不增强。增强与冻结 raw feature cache 互斥，避免缓存污染。

**数据结果：** 当前 99 个 raw session 全部重建并通过 v5 audit，共 1,917 chunks / 7,668 actions；MVP train 为 1,537 chunks（79 sessions），val 为 380 chunks（20 sessions），session 零重叠且两侧均覆盖 `travel`/`decipher`。批量报告位于 `data/new_vla_raw_sessions/vla_chunks_v5.audit_summary.json`。

**已知限制：** 采样和增强不能替代类别平衡。动作仍偏向 stop/north，camera dx=0 仍是多数类；后续训练必须继续观察 image/history A/B、各 head macro-F1、per-class recall 与预测分布，并使用全局类别权重或分桶采样评估是否缓解坍塌。
