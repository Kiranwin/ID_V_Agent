# 01 · 历史代码审查报告

> 审查对象：旧项目 `Z:\temp\FastVLA\FastVLA`（协作产出，文档混乱）
> 本文件是重构的**输入依据**，不是新项目文档的一部分。新项目文档统一在 `docs/` 下。

## 背景

旧项目目标是「第五人格求生者 VLA agent」。工程实（采集/数据/模型/部署脚手架质量高），但存在结构性缺陷，且文档（CLAUDE.md / design / HANDOFF / 审查报告）分属不同阶段、互相矛盾、难以维护。

本新项目 `ID_V_Agent` 以旧项目为蓝本重构：**保留已验证核心，修复致命问题，砍掉冗余，重排为面向 VLA 的统一包结构**。

## 已验证（重构时保留）

| 模块 | 说明 |
|---|---|
| 采集管线 | DXGI(dxcam) + pynput 统一 `perf_counter_ns` 时钟 |
| 破译状态机 | 处理「按 Q 自动破译」的隐式状态语义，含 90s 误触保护 |
| JSONL 数据格式 | intent_vector(16d 正交) + skeleton + category_id + 4 连续值 |

| 黑杰克 RuleAgent | 闭环跑通过，但绑定黑杰克 schema（见 P13 收敛） |

## 致命问题（P1-P3，本新项目已处理）

- **P1 快慢互为前置死结**：FastController 依赖慢层意图，慢层需闭环验证，闭环依赖快层 → 新项目补**律师版规则 agent 兜底**（`agent/rule_agent.py`），先让闭环转起来。
- **P2 校准(QTE)信号被抹**：破译状态机把解码期 Space 重写为 INTERACT_HOLD，模型学不会校准 → 状态机保留 `decode_calibration` 标记帧（见 `labels/state_machine.py` 的设计），即使不重录也能用视觉辅助标注补救。
- **P3 学习链路未验证**：checkpoints 全空、损失权重/LoRA 配置/FP16 耗时全是纸面 → 新项目把「先跑通单 epoch」列为 M2 第一步，smoke_test 覆盖模型 forward。

## 重要问题（P4-P8）的处理方式

- **P4 动作类别不平衡** → `labels` 输出类别分布统计脚本；`FastController` 支持 `class_weights`。
- **P5 意图是按键推断的弱监督** → 意图体系保留启发式映射为基座，但明确标注「HEAL/RESCUE 依赖视觉」是后续增强项，不当作已解决。
- **P6 慢层实际刷新 0.2-0.3Hz 非 2Hz** → 部署层不承诺慢层高频；事件总线只在关键事件时触发重规划（省算力）。
- **P7 鼠标灵敏度域偏移** → `configs/schema.py` 里 `cam_pixel_scale` 显式配置，录制基线需记录采集时游戏灵敏度。
- **P8 受击打断破译感知不到** → 感知层预留「受击事件/破译进度条消失」接口，作为状态机退出条件的视觉辅助。

## 方向性问题（P9-P12）

- **P9 快层 VLA 化** → 新项目快层用可插拔 `Policy` 抽象：M2 是 SigLIP2 小策略网络，M3 换 3B VLA 主干不破坏上层。
- **P10 DROP_BOARD 占位类** → 保留但标注「需视觉判定区分翻窗/翻板」，决策语义合并进 VAULT。
- **P11 架构无记忆** → 新增 `agent/memory.py` 对局记忆（监管者最后位置、各机修机进度、地窖位置），作为慢层的公共状态。**架构级提升**。
- **P12 被律师锁死** → 首发锁律师是「已确认决策」，感知/快层与角色技能解耦，换角色只换技能模块。

## P13 收敛（本新项目新增的清理决定）

- **黑杰克整套**（keymap_blackjack / schema_blackjack / remap 脚本）：已确认首发只做标准模式求生者，移出主代码，数据仍留在 `data/sessions`。
- **GroundingDINO / YOLO 测试残留**：未进主训练/部署主链路，不并入新项目。
- **SpatialPlanner**：降级为可选组件，不作为慢层主路径（P6 已说明刷新率天花板）。
