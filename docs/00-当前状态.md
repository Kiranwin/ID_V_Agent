## 1. 当前结论

项目当前处于：**VLA 数据闭环与模型骨架阶段，尚未进入真实 VLA 训练或 VLA 实机运行**。

最终架构已经冻结为：

```text
任务指令 + mode
        ↓（episode 内缓存一次）
单帧视觉 backbone M0（每个采集帧最多一次）
        ↓
FrameFeatureCache（最多 8 帧）
        ↓
共享时序编码器
   ┌────┴────┐
   ↓         ↓
慢头       快头
intent/    action chunk
subgoal/   + confidence
context    + stop/replan
```

这是**单模型共享基座 + 两个任务头**，不是两套独立微调模型。捕获频率和快头频率解耦：
例如捕获 30 FPS，快头按固定 deadline 运行 15 Hz，慢头约 1 Hz 或事件触发。

## 2. 已冻结的协议

| 项目 | 当前约定 |
|---|---|
| 平台 | Windows PC 互通版，官方自定义剧本/训练营 |
| 角色 | 求生者·律师 |
| 训练主线 | VLA action chunk；旧 BC 管线不再是训练主线 |
| 输入 | 单帧 backbone 特征 + 8 帧以内时序窗口 |
| 动作块 | 4 步；九方向移动、五档相机、六个按键位 |
| 文本条件 | instruction/mode embedding 每个 episode 缓存一次 |
| 慢条件融合 | intent/subgoal/context/mode → MLP → FiLM |
| 慢标签 | 每帧存储，训练用 0.5～2 秒时间采样 mask |
| 顶层意图 | `decipher/kite/rescue/rotate/travel/search/gate/idle` |
| subgoal | `subgoal.v1`，由规则从状态/检测/事件派生，人工不逐帧标 |
| VG 框 | YOLO 三类：`cipher_visible/cipher_highlight/interact_prompt` |
| 帧状态 | `decoding/idle/walking/chased`；默认自动推断，chased 并入 walking |
| 精度 | RTX 2080 Ti 使用 FP16 + GradScaler，不使用 BF16 |

## 5. 唯一下一步顺序

### 用户需要做

1. 新录制 session 必须先运行 `validate_vla_raw.py`；
2. 用 `init_intent_segments.py` 生成候选片段，只人工确认顶层 intent；
3. 运行 `validate_intent_segments.py`，再构建 v4 chunks；
4. VG 数据运行 `infer_frame_states.py`，抽查后生成 annotations、grounding 和 frame QA。

### 代码侧随后做

1. 从 v4 JSONL 读取真实图片并接入 Qwen 单帧特征接口；
2. 写最小 `train_vla.py`：dummy backbone → forward → loss → backward → checkpoint；
3. 在 2080 Ti 上 FP16 跑一个小 epoch，记录显存和延迟；
4. 用 WK/VG 做共享 M0 的辅助训练；
5. 用 ACT action chunks 做快慢头训练；
6. 离线回放评估，再做自定义剧本 dry-run；
7. 最后才允许极短真发送测试。
