# 00 · 当前状态与唯一执行入口

> 最后更新：2026-09-08。本文只保存当前主线、可训练数据和放行条件；历史实验细节见
> [18-架构变更历史.md](18-架构变更历史.md)。开始 VLA 工作前还必须阅读根目录
> `GOAL_STATUS.md`，它保存长任务断点、实验产物与禁止部署状态。

## 1. 当前结论

目标是仅在官方自定义剧本/训练营中，由同一个 VLA 模型自主完成：

```text
开局 → 转镜头找密码机 → 靠近 → 出现 Q 提示 → Q → 自动进入破译
```

尚未有可部署 checkpoint。任何 checkpoint 在完整离线视觉依赖、类别/过度动作与
sandbox dry-run 均通过前，均不得启用 `--send-input`。WK/VG 当前不作为 ACT 初始化：
ACT 从基础 Qwen 训练，M2/VG 禁用。

目前已确定：相机动作不是“模型没看图”，而是 Raw Input replay 同时包含搜索、移动、
绕障和路线跟随，导致画面相似时 h0 replay bucket 仍可能不同。为此不改写 replay，
而是增加训练期视觉事实与镜头控制语义标签。详见 [03-数据格式.md](03-数据格式.md)
第 7 节。

## 3. 当前模型与已知限制

- v25 起的滚动因果协议：模型可预测 4 步，但训练、评估和执行都只消费第 0 步
  （6 帧约 200 ms）后重新观察；旧多步连续执行 checkpoint fail-closed。
- m26 固定 `camera_prior_scale=0`：相机决策不能由动作 history prior 改写；
  `history_zero` 必须等同 normal。
- m27 在直接视觉特征上预测 `phase/target/steering/path/desired_turn_dx/dy`，并将
  **模型预测 logits** 融入 camera head。runtime 不读取任何 JSONL 真值。
- 控制语义数据极少（48/46），且标注覆盖不足以证明可泛化的绕障策略；增加训练轮数
  不是主修复。后续应补充独立 session 的 search、目标获取、左右绕障、靠近/Q 提示等
  组合标签。

## 4. 训练与验收入口

每次重建/训练前先跑：

```powershell
python -m idv_agent.scripts.audit_mvp_training_data `
  --dataset data/mvp_vla_v5_event_centered_decision_label_v3_rebucket675 `
  --grounding-annotations data/mvp_act_grounding_pool_v1/act_grounding_annotations.jsonl `
  --camera-control-train data/mvp_act_grounding_pool_v1/camera_control_train.v2.rebucket675.annotated.jsonl `
  --camera-control-val data/mvp_act_grounding_pool_v1/camera_control_val.v2.rebucket675.annotated.jsonl `
  --class-balance data/mvp_vla_v5_event_centered_decision_label_v3_rebucket675/class_balance_h0_rebucket675.json `
  --output reports/mvp_v5_rebucket675_training_data_audit.json
```

训练时必须显式分离 train/val control 标注，开启训练图像增强、关闭 raw feature cache，
使用 `execution_horizon=1`、`camera_prior_scale=0`。标准调用见
[10-VLA训练策略.md](10-VLA训练策略.md)。

每个候选 checkpoint 的放行顺序固定为：

```text
训练行为（有限 loss/grad）
→ held-out camera-control 语义指标
→ normal / image_zero / image_shuffle / history_zero 视觉依赖门禁
→ 稀有类 recall、多数类 recall、0 桶误转率
→ 官方沙盒 dry-run 全流程
→ 才能考虑 --send-input
```

image-zero 与 image-shuffle 中 move/camera/intent 都必须相对 normal 明显下降；
“输出被图像改变”不等于“输出因此更正确”。

## 5. 数据重建顺序

```text
record_vla（只采集）
→ validate_vla_raw
→ init_intent_segments / 人工确认 intent_segments
→ build_vla_chunks 或 train_vla_chunks_v5
→ prepare_mvp_data --event-centered（仅整 session split）
→ grounding / camera-control 标注与校验
→ audit_mvp_training_data
→ train_vla
```

完整字段含义、边界和禁止事项见 [03-数据格式.md](03-数据格式.md)。视觉标注工具与
grounding/control sidecar 流程见 [14-VG标注与消费路径.md](14-VG标注与消费路径.md)。
