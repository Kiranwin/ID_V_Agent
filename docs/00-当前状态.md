## 1. 当前结论

项目处于：**VLA v5 数据管线、三阶段训练（WK→VG→ACT）框架和小规模 GPU 训练均已跑通；尚未有可用于实机 dry-run 的合格 checkpoint，尚未进行正式泛化评估**。

当前架构：

```text
任务指令 + mode
        ↓（episode 内缓存一次）
单帧视觉 backbone M0（每个采集帧最多一次，Qwen3-VL-4B + LoRA）
        ↓
FrameFeatureCache（最多 8 帧，最少 3 帧）
        ↓ FiLM(condition_{t-1})
   ┌────┴────┐
   ↓         ↓
slow_temporal  fast_temporal     ← 分离 GRU，2026-09-03 起
   ↓         ↓
慢头       快头
intent/    action chunk
subgoal/   (move_dir/camera/buttons/duration)
context    + confidence + stop/replan
```

这是**单模型共享 backbone + 分离时序编码器 + 两个任务头**。分离时序编码器消除了慢头
（离散分类）和快头（连续控制）对同一份循环权重的竞争；FiLM 条件融合仍在分叉之前，是
两者共用且可控的耦合点（`detach_slow_condition` 开关）。详见
[15-快慢VLA接口与时序缓存协议.md](15-快慢VLA接口与时序缓存协议.md) 第 3、6 节和
[18-架构变更历史.md](18-架构变更历史.md)。

捕获频率和快头频率解耦：捕获 30 FPS 写入缓存，快头按固定 deadline 独立运行（目标 15 Hz），
慢头约 1 Hz 或事件触发。

### 3.3 VLA ACT

已有 raw session 保留原始数据；历史批次曾生成 v4 chunks。v5 主线要求从 raw session 重新提取 `per_frame_actions.csv`，并生成独立的 `vla_chunks_v5.jsonl`，不覆盖旧 v4。

当前磁盘中的 99 个 raw session 已全部重建 v5，使用 `anchor_stride=12`、`history_stride=3`、`history=8`、`horizon=4`、`macro_frames=6`；总计 **1,917 chunks / 7,668 actions**，每个 session 的 audit `gate_pass=true`。总体慢标签为 `travel=1,729`、`decipher=188`；camera dx 桶为 `-2:578/-1:683/0:5,166/1:560/2:681`，Raw 像素 dx/dy 非零动作分别为 4,128/3,455；记录级 schema、路径、alignment、相机像素桶一致性逐条校验均为 0 错误。批量审计见 `data/new_vla_raw_sessions/vla_chunks_v5.audit_summary.json`。

MVP 已从上述新 v5 重建：train **1,537 chunks（79 sessions）**，val **380 chunks（20 sessions）**；train/val session 零重叠，两侧均包含 `travel` 与 `decipher`，所有纳入记录均通过 `validate_v5_record`。当前动作仍存在真实分布偏斜：7,668 个动作中 stop=1,959、north=4,660，camera dx=0 为 5,166；这是训练采样/损失权重和覆盖设计的问题，不是数据格式校验错误。训练增强仅作用于训练 forward，采用共享 window 参数的 hue ±0.05、saturation/brightness/contrast 0.8～1.2、平移 ±8 px；验证路径和 raw/v5 文件不增强。

三阶段 checkpoint 均已产出（`checkpoints/M1_WK`、`checkpoints/M2_VG`、`checkpoints/M3_ACT/*`），但**当前没有任何 M3_ACT 候选达到可进入 dry-run 的标准**：多轮 500-step 规模实验反复暴露同一组问题——移动头塌缩为多数类、按键正例召回可能为 0、慢头意图准确率明显偏低（约 16%~25%）。分层采样能修复按键召回，但不能同时修复移动塌缩，需要独立的移动类别权重（基于全局统计而非 batch 内频率）。慢头准确率长期偏低是触发"分离时序编码器"这次架构变更的直接原因（详见 [18-架构变更历史.md](18-架构变更历史.md)），分离后的重新训练结果尚未产出。

逐次实验的详细数值不再堆积在本文，见 [17-三阶段训练继承协议.md](17-三阶段训练继承协议.md) §5 的结论摘要和对应 commit。

## 5. 唯一下一步顺序

### 数据侧（用户执行）

1. 新录制 session 先运行 `validate_vla_raw.py`；
2. 用 `init_intent_segments.py` 生成候选片段，人工只确认顶层 intent，再跑 `validate_intent_segments.py`；
3. 构建 v5 chunks（`build_vla_chunks.py --schema-version vla.action_chunk.v5`，输出命名为 `vla_chunks_v5.jsonl`）；
4. VG 数据跑 `infer_frame_states.py`，抽查后生成 annotations/grounding/frame QA。

### 训练侧（代码执行）

1. 先将其余合格 raw session 全部重建为 v5，并运行 v5 audit；
2. 用当前分离时序编码器架构，基于 v5 数据跑一次正式规模训练（`--init-checkpoint checkpoints/M2_VG --sampling stratified`），对比慢头验证准确率是否从约 16%~25% 明显提升；
3. 如果仍不收敛，用 `detach_slow_condition=True` 做对照实验，判断 FiLM 残留耦合是否仍是主因；
4. 同时解决移动方向塌缩：基于训练集全局统计的类别权重或九方向分桶采样；
5. 用 `evaluate_vla.py` 扩展到完整留出 session，按意图/状态分桶报告指标；
6. 接入 VLA dry-run 与滚动 action chunk 调度（`run_agent --mode act`），确认安全门和延迟预算；
7. 仅在官方自定义剧本/训练营进行极短真发送测试。
