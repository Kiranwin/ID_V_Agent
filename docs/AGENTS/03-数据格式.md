## 0. 当前设计：MVP v6，20 FPS 采集 / 稀疏视觉闭环（2026-09-08）

**2026-09-09 操作入口更新：** 后文手动填写 CSV 的早期步骤由网页工作台取代。
用户直接在工作台标注 `navigation_review_with_state.csv`，每个 session 独立保存于
`data/raw_sessions/<session>/`。工程/源 JSON 快照仍在 annotations 目录。以
[V6 工作台说明](../tools/data-workbench-v6.md) 的网页步骤和存储位置为准，旧工作台
不再兼容 V5；原始图像和事件保持不变。

**本节取代下方旧 v5 的新数据设计要求；下方保留作历史实现说明。**
本次冻结的是数据与时间契约。新标注工作区、校验和训练格式导出已实现；现有
`train_vla` / `run_agent` 仍是旧 m28/v5，不能消费 v6。模型头、稀疏时间输入、
训练器和实机 runtime 必须一起升级并重训，不能仅把 CLI 改为 20 FPS 就运行旧权重。

### 0.1 任务范围与层级

MVP 的唯一顶级任务为 `decipher`（破译）：找到一台可用密码机、靠近、交互，并确认
进入自动破译。**用户最新明确的 Q 子任务是：当前帧 interact_prompt=true → Q token，
false → NO_Q；允许短时间连续触发。** Q 子任务的训练和验收不需要 Q 后破译成功
画面，也不要求复现人类按键时刻。**但完整顶层控制必须认识当前是否正在破译**，
`facts.decoding` 是顶层状态监督；动作后的 `outcome` 是另一项结果审计，不能混为
一谈。当前状态监督不阻塞独立 Q 样本。QTE、遇心跳撤离暂不训练。
完成五台、中心机优先、全图分散修机仍是后续任务：目前没有地图/机器进度/队友
位置/多目标记忆输入，不能把这些不可观测策略写成当前模型必须预测的真值。

同意只保留一个顶级意图。**常量任务用条件输入，不再训练单类别 intent CE**。
真正指导底层的顶层决策是下面的 `decision.phase`。事实、决策和动作分开：
`interact_prompt=true` 是画面事实，`interact` 是当前决策，`q=true` 是执行命令。
Q 的直接视觉监督优先：导航 phase、过去按过 Q、是否已确认 decoding 都不否决它。

| 顶层阶段 `phase` | 判定依据（只看截至观测时刻的画面和已执行日志） | 可学的底层行为 |
|---|---|---|
| `search` | 当前窗口没有可定位的目标/目标失去且无可靠历史轨迹 | 搜索镜头；场景允许时可移动，不硬编码固定转向 |
| `approach` | 目标已确定，当前主要目标是缩短到交互点的距离 | 移动并进行路径修正；不要求相机始终盯机器 |
| `align` | 当前主要目标是修正视角或进入交互点 | 小转向、位置修正、必要时暂停移动 |
| `interact` | 当前帧出现标注类别 interact_prompt 的 UI | 输出 Q；连续有提示的帧仍是 Q 正样本 |
按 Q 后尚未确认是否进入破译仍标为 `interact`；“已发送 Q、距今多久”属于独立
execution feedback，不再创建第六个 phase。这样标注词表与部署头完全一致。
| `maintain_decode`（完整顶层必需） | 当前及历史画面确认正在自动破译 | 顶层指导保持、停止无关导航；Q 仍按当前 interact_prompt 标注 |

approach 与 align 可以往返；不是不可逆六段线性流程。不明确就 `phase=null`，
该项 mask=0。选中哪台机用 session 内 `target_track_id` 记录，ID 只供配对和
审计，不当全局类别输入神经网络。MVP 接受“当前可见且可接近的机器”的一致演示。
当多个候选必须依赖超过 1.4 秒的记忆才能判定时，标记目标选择不确定并屏蔽相关
动作；不能一边宣称无记忆模型，一边让它复现人类的隐藏路线选择。

纠正前次分析：没有 `approach_cipher` 这个名称不等于完全没有接近示范，原来的
`move_to_target` 可以包含接近。真正需补的是**明确的阶段含义、当前目标及动作
后的证据**。共享状态配合多个输出头也能学会一致动作，不因输出分头就必然失败；
必须用联合动作指标验证，不能把猜测当作失败根因。

### 0.2 20 FPS 采集与约 6 FPS 编码的时间设计

用户提供 Qwen 视觉约 6 FPS 基线，本次没有重新测量。选择保留冻结 Qwen 视觉塔和
m28 shared state + predicted belief planner，重新设计调度与时间输入：

```text
20 Hz 抓帧 → 最新一帧槽（覆盖积压）
                 ↓ 单个 GPU worker，最大 5 Hz 编码；每帧只编码一次
          最近 3～8 个真实视觉结果 + 原始 capture 时间
                 ↓ 同次顶层 phase / facts / steering 预测
                 ↓ soft(predicted beliefs) + z → 一次 h0 联合动作
          有效结果槽 → 独立 CPU 执行时钟（建议 50 Hz）
                         ↓ 200 ms 动作到期释放
                 等待 capture 时间晚于本次动作结束的结果
```

5 Hz 是**视觉吞吐上限**，不是保证 5 Hz 完整闭环。167 ms 编码 + 200 ms 动作 +
抓帧/调度相位，保守完整闭环约 2～2.7 Hz，须测量 p50/p95/p99。MVP 首先接受
较慢但可解释的闭环；若 held-out 接近/对齐仍明显因带宽不足失败，再测试轻量视觉
编码器/蒸馏，不能现在假定多加一个头能把 6 FPS 变成 20 FPS。

同一视觉结果的幂等消费用于防止消息重复投递，**不等于同一提示只许按一次 Q**。
连续新画面只要 interact_prompt 仍可见，就继续输出 Q；提示消失后输出 NO_Q。
短时连续 Q 合法，不加“等待 decoding 确认后才可再按”的硬条件。高频 CPU 只负责
动作计时、到期释放、处理新结果，不负责虚构新的视觉证据。模型和 GPU 放在单一
worker，避免多个线程对同一 CUDA 模型并发推理。失效/停止后的晚到结果丢弃。

| 时间字段/参数 | v6 设计 |
|---|---|
| raw capture | 20 Hz；真实时间戳权威，丢帧不能重编号伪造成固定间隔 |
| encoded visual history | 3～8 帧，标称每 200 ms 一帧；8 帧覆盖约 1.4 秒 |
| history 缺失 | 使用真实短窗口和 valid mask；不复制旧帧伪装新观测 |
| timing input | 每帧相对最新观测的时间 + 观测到执行的 age；进入 deployed state trunk |
| action duration | 固定 200 ms，20 FPS 下约 4 帧；执行按 wall clock 而非帧数 |
| observation→action offset | 工作区暂用 200 ms，显式标记 design assumption；实测后版本化重建 |
| command result | capture_ns / ready_ns / submitted_ns / ended_ns / result_id |
| 消息去重 | 每个 result_id 最多消费一次；连续新结果的 Q 不去重，允许短时重复 |
| max feature age | 暂定 400 ms，仅调度合同，须按实测评估；不是模型已可用声明 |

不能沿用“8 帧/stride=2”的初稿：它要求 10 Hz 视觉，仍超过 6 FPS。不能把真实
时间差只送旧 GRU：当前 m28 的部署主路不消费该 GRU。改动后必须验证 time/age
确实进入 deployed state，并对全零、抖动、缺帧分别评估。

### 0.3 原始 session：保存事实，禁止自动裁掉无输入结果

新录制默认：`--fps 20 --output data/raw_sessions`，F9 后先保留约 2 秒静止画面，
再开始演示；F9 停止后可继续保存 2 秒结果画面。该尾部对 Q 子任务是可选信息，
仅有提示帧/无提示帧也能训练 Q。F10 或 max-seconds 上限立即结束不否决已知 Q 标签。

```powershell
python -m idv_agent.scripts.record_vla --fps 20 --output data/raw_sessions --post-stop-seconds 2
```

原始目录仍是 `frames/ + frame_timestamps.csv + events.csv + mouse_deltas.csv + meta.json`。
`raw_schema_version=idv.raw_session.v2` 与 action schema 分开。旧 `vla_schema_version`
字段暂留兼容旧校验器，不代表数据已是 v5/v6 训练样本。

默认不再按首次/末次输入裁剪；`--trim-idle-boundaries` 仅保留历史兼容。破译是自动
持续行为，无输入是重要正证据。原始按键 repeat 事件照存，在派生层去重成边沿；
Raw Input 使用整数 counts 与原始时钟，不称作角度或缩放截图中的像素。

采集检查：帧文件可解码、时间单调、meta 范围、输入监听健康、有效 FPS/最长缺帧、
窗口大小和输入配置。数据工作区另外记录 sensitivity/DPI/分辨率/FOV（可见设置）、
角色/地图/出生点/录制轮次；未知就写 unknown，不能杜撰。鼠标控制码本必须绑定
输入增益配置，同样的 counts 不保证在不同灵敏度下产生同样转角。

### 0.4 所有人工标注的位置和字段

```text
data/raw_sessions/<session>/                    原始文件，只读
data/annotations/mvp_v6/<session>_prompt_q/
  manifest.json                                 raw hash、协议、scenario_group、split
  decisions.jsonl                               决策端点全集 + 待标真值
data/derived/mvp_v6/<dataset_version>/            审核后训练格式导出
reports/mvp_v6_design/                           审计/接触表/桶比较
```

不再要求维护互相游离的 intent_segments / frame_states / grounding / camera_control
四份文件。以**一个决策端点记录**为唯一真值；连续阶段可在标注界面批量填充，但必须
在边界复核，图像框不能不经检查跨帧线性插值。旧 YOLO 可以预标，默认 pending。

| 组 | 字段 | 规则与用途 |
|---|---|---|
| 身份 | session_id, frame, observed_ns, history_frames, history_timestamps_ns | 自动生成，严格因果，不人工改 |
| 过去执行 | last_q_down_ns | 只审计；不作为 Q 输入，不用它抑制连续正标签 |
| facts.scope | in_scope / out_of_scope / uncertain | QTE、追逐、菜单等不混入 MVP 动作监督 |
| facts.cipher_visibility | visible / highlight_only / absent / occluded / unknown | 看不到实体但有游戏轮廓提示时单独表示；unknown 不是负例 |
| facts.target_bbox | normalized xyxy 或 null | 只标当前目标的实体/可见轮廓；遮挡未知不画想象框 |
| facts.target_track_id / target_evidence | session 内目标身份、entity/highlight/历史证据说明 | ID 供追踪审核，不喂网络作可记忆类别 |
| facts.interact_prompt / prompt_bbox / prompt_target_link | true/false/null、可选提示框及关联信息 | interact_prompt 是 Q 的唯一真值来源；Q 不要求候选；prompt 出现即足够接近并自动停止导航监督 |
| facts.decoding / decoding_evidence | true/false/null + 可核对帧/进度UI/动画证据 | Q 事件不能直接生成 true；只有提示图标也不能证明正在破译 |
| facts.path | direct / detour_left / detour_right / blocked / unknown/null | 只标局部可通行路线；不是“把目标居中”的同义词 |
| decision.phase / steering | 阶段；target_center/path_follow/search_sweep/hold | 导航标签；只训练 Q 时可全部留空 |
| decision.target_choice_reason / track_valid_in_history | 当前选机理由、窗口是否支持目标持续性 | 解释隐含路线和多目标歧义，未知动作不强行监督 |
| action_review.source | accept_replay / correction / exclude | 仅决定移动/相机监督来源；exclude 不屏蔽已审核 Q |
| action_review.move / camera_command | 0..8 移动 / 两轴码本 counts | 导航动作，需单独审核；不能阻塞 Q 样本 |
| action_review.q | 通常留 null 自动派生；若手填必须等于 interact_prompt | 导出时写入派生 q 与 q_source；不能再填人类未按=0 |
| action_review.reason | 纠正或排除原因 | 人类失误、动作窗口混合、观测不足、输入丢失、范围外等 |
| outcome | status、first_decode_frame、confirmed_through_frame、evidence、target_progress | 可选审计；Q-only 导出无需填写，不作为当前动作输入 |
| review | pending/reviewed、annotator、reviewer；另有 review.interact_prompt | 支持只审核提示字段并独立导出 Q，其他标签可 pending |

`reachable` 不再由“有机器框”推出，也不再和 prompt 重复标成相同变量。MVP 使用
标注为 interact_prompt 的 Q 提示作为 Q 真值，目标关联信息不额外决定是否输出 Q。
物理距离没有真值时不标米数；
`target_progress` 可标 closer/same/farther/unknown，但镜头旋转造成 bbox 变大
不能单独证明接近，结果需结合地标/角色移动复核。该进展标签首期用于诊断，不加
未经验证的奖励/世界模型损失。

### 0.5 从事件到唯一动作目标

在绝对时间区间 `(action_start_ns, action_end_ns]` 积分：

1. WASD 根据真实 held 时间统计 occupancy；重复 key_down 不重复开启状态。
   四键都落在 ≤20% 或 ≥80% 才提出稳定的 9 方向标签；中间值、对向同时按住
   标 mixed，交给 review 修正/排除，不能平均成看似正常的 stop。
2. 鼠标保存 signed sum 和 absolute sum，检查窗口内部反向抵消；净和才映射执行
   桶。大量反向抵消窗口优先排除/更密审查，不从净零推断“人没动镜头”。
3. Replay 中 Q 只记录去重后的 down 边沿作为人类行为证据。**训练 q 不从它生成，
   而是 q_target=当前 interact_prompt。** 人类没按但提示在，仍是正样本；人类按过
   但提示已消失，仍是负样本；未知可见性则 q mask=0。
4. `accept_replay` 用抽取建议并人工确认其适用；`correction` 纠正 move/camera
   并说明理由，原 replay 永不覆盖；无法判断则 exclude navigation，Q 保留独立
   的 mask。纠正动作未经执行，其 outcome 仍属于 replay，绝不可写成纠正
   动作已成功。
5. facts 由 observation time 标注，动作 label 可来自未来窗口，outcome 由之后的
   帧验证。这三者各守因果边界，禁止由未来 Q 反推 observation 的 phase。

Q 必须学会直接的视觉响应，**不要求 phase=interact、move=stop、camera=0 或
decoding=false 才能得到 Q 正标签**。移动和相机标签另行审核，其未知/排除不影响
Q。`interact_prompt=true/false/null → Q/NO_Q/mask=0` 适用于联合动作模型、快层、
独立轻量视觉动作模型；物理执行器只翻译模型 token，不读取人工标签代替模型。

Q 专项训练把独立 BCE/二分类损失作用到真正用于输出 Q 的 logit。禁止同时在
同一个输出上加 replay-Q loss。提示 detector 的辅助 loss 不能代替执行 Q token 的
验证。`prompt_q_loss` 已提供，旧 v5 trainer 尚未接入；不能声称当前权重已学会。

Q 专项验收按独立 session/场景：有提示的 Q recall、无提示的误 Q 率、提示出现到
首个 Q 的延迟、提示消失后是否仍输出 Q。连续新帧 `1,1,1,0 → Q,Q,Q,NO_Q` 应通过。
回归样例要求全部命中，但合成/单元测试不等于模型真实图像准确率。提示遮挡/跨场景
消融应证明是 UI 内容驱动，而非只记住出现时刻或固定位置。

### 0.6 鼠标码本：这两条新录像的决定

当前决定：**暂保留 5 桶 `[-110,-25,0,25,110]` counts/200 ms，不缩小到 ±12，
不直接加第 7/9 桶**。原始 counts 全量保留，便于后续重算。20 FPS 与旧 30 FPS
都使用 200 ms 动作时长，所以不能按 20/30 比例缩放命令。

`reports/mvp_v6_design/camera_audit.json` 对两 session 用 0/50/100/150 ms 四种
窗口相位比较；下面是四相位的非零窗口 MAE 均值（counts；相关样本，不是验证集）：

| 码本 | 边缘→中心 `210720` | 局部微调 `210912` |
|---|---:|---:|
| 旧 5 桶：0/±25/±110 | 25.04 | 10.91 |
| 5 桶缩小细档：0/±12/±110 | 26.38 | 14.24 |
| 加微档：0/±8/±25/±110 | 23.53 | 9.54 |
| 加大档：0/±25/±110/±200 | 11.58 | 10.91 |

加微档带来有限重建改善；加大档主要拟合一段快速扫视，不能证明更少过冲。
两条都是“转向+前进+Q”的混合导航示范，不是纯增益标定；高频 HID 每个 1～2 count
事件不能直接当宏动作桶。两 session 的总 dx 分别是 201 和 326，这也说明
“微调 session”不等于每个 200 ms 动作都微小。

若后续要换桶：固定灵敏度，分别录左/右纯镜头 5/10/20/40/80/120/200 counts
量级、停止、持续移动中的修正，至少跨独立 session/场景；标出目标中心误差变化、
过冲、停转成功率。训练分组拟合候选，独立组比较控制成功而非仅重建 MAE，再冻结
命令幅度/边界/版本。首期不要靠新增稀有类别弥补监督和延迟错误。

### 0.7 标注顺序、抽样与准入

1. **Raw audit**：检查时钟、图像、掉帧、输入、配置，生成文件 SHA256。原始证据
   损坏与任务失败分开；失败示范仍可保留已知事实，错误动作不自动纳入 BC。
2. **先定分组**：按整 session，且同地图/出生点/同连续录制轮次用 scenario_group
   绑定。三条新演示看起来场景相近，先放同一待分配组；不能拆成三份伪造独立验证。
3. **生成端点再标注**：标称 200 ms 视觉间距生成 endpoint，并额外加入 Q 前后 review
   点；不再先标 1,380 张图却只让 128 个 endpoint 入训。记录端点命中率为 100%。
4. **事实与决策标注**：Q 子任务只需标 interact_prompt=true/false/null 并完成该字段
   review；全任务再填写 phase、目标、decoding、局部
   路径；严禁先看动作/未来再猜状态。只读原图中真正可见内容，unknown 可屏蔽。
5. **动作审核**：再显示 replay 摘要和轨迹，选 accept/correction/exclude；联合检查
   移动与路径一致；Q 自动从已审核 interact_prompt 生成，不能因人类未按而改成 0。
6. **结果复核（Q 子任务不要求）**：解锁 after 画面，可给 confirmed_decode/no_entry/
   insufficient_tail/unknown。自愿报告 confirmed_decode 时保留 ≥1 秒证据要求，
   但没有该证据仍可训练并验收 Q token。
7. **独立复核**：全部 Q 正样本、全部 correction、阶段/目标切换、absent 与未知样本
   必查；其余抽查，分歧留 pending。检查 phase 与事实合法性及事件时间一致。
8. **导出审计**：分组零泄漏，标签来源/版本固定，未知各项 mask=0；只有一个 action
   target。拒绝未审核/改写 replay/未来图像/旧时间协议混用。

覆盖维度是 search/no-target、left/center/right、approach/direct/detour、near prompt、
Q 前有提示（人类未按也标 Q）、连续有提示重复 Q、提示消失 NO_Q、失败/偏航恢复。
采集配额按独立
session 和状态覆盖制定，不能承诺某个任意数量必定足够。先标完整 10～20 条覆盖
这些阶段的 pilot，检查标签一致性及每阶段正负比例，再扩大。

训练 sampler 初始按 session 均匀，再在同 session 的阶段里均匀选择；Q 邻域保留
其 event_id，避免十个相邻点算十次独立成功。class weights 从最终唯一 action target
和真实 mask 的 train 分布计算，评估沿用同一目标；replay 拟合指标单独列出。
全任务固定小集合覆盖 search/approach/align/interact；Q 专项只要求有/无提示两类，
不等待 verify/maintain 标签。先检验能否拟合，
再 held-out；总 loss 下降/梯度<100 不代替阶段、相机停止、Q 和联合动作指标。

### 0.11 顶层决定做什么，快层落实动作，执行结果回到顶层

用户明确：独立 prompt→Q 快速反应不能替代顶层对破译状态的理解。最终设计分为：

- `task=decipher`：整段目标“去修密码机”，由任务输入指定。
- `facts.decoding`：当前事实上是否已开始自动破译，由当前/历史图像中的可辨认 UI、
  动画/进度等证据估计；不是“任务=破译”的同义词。
- `decision.phase`：现在要执行搜索/靠近/对齐/交互/维持哪一个子任务。训练时人工
  对照截至本端点的图像、目标及已执行记录标注，运行时由学习到的顶层决策模块预测。

phase 的决定依据是“任务条件 + 目标位置/持续性 + 交互提示 + 当前破译状态 +
局部通行情况 + 截至当前的执行反馈”，不是帧号、预定脚本或独立看某一个键。
例如：同一台机器已在正前方但还远，通常以 approach 为主；位置很近但交互点尚未
对好，以 align 为主；有提示进入 interact；实际观察到破译进入 maintain_decode。
approach/align 可同时包含移动和镜头调整，phase 表示当前主要目标，不硬限制动作。
依据不足时保持不确定，不为凑齐五阶段强行创造标注。

```text
当前/历史图像与时间 → 共享视觉状态
       ├→ 提示/目标/实际破译状态估计 → 顶层 phase + 目标 + steering/path
       │                                  ↓ 预测条件（不是真值标签）
       │                              动作 planner → move / camera
       └→ 最新视觉的快速 Q 预测 ───────────────────→ Q / NO_Q
                                              ↓ 单一命令汇合点
                                           动作执行器
                                              ↓ 实际已发送动作 + 时间 + 成功/失败反馈
                                   顶层记录“尝试交互”，等待新图像修正状态
```

Q 也在顶层任务链里：interact 表示“现在应交互”，顶层指导导航停止扰动并关注结果；
快层负责精确的可见 UI→Q 时机，不等低频 phase 刷新。Q 发送后的反馈必须回到
顶层，不能一边底层已按 Q、一边顶层仍盲目导航。反馈要区分“模型想按”“执行器
已发送”“游戏画面已开始破译”，三者不能用一个 bool 混写。

快层不读取人工 prompt 标签：真实运行必须从图像预测。若独立轻量视觉支路存在，
其 predicted prompt 概率/时间也回传顶层；是否达到 20 FPS 需测量，不能假定一个
轻量输出头能突破 Qwen 视觉 6 FPS。现阶段可共用一次 Qwen 编码，不要求再增加
一个大语言模型做逐帧文本推理。

命令只有一个汇合点：导航 planner 拥有 move/camera，快速 Q 输出拥有 Q 通道；
顶层的 interact 是意图/阶段，不另发第二份竞争 Q。当前用户合同仍是有 prompt
输出 Q、无 prompt 不输出、允许短时连续；顶层 phase 迟到、已按过 Q 或状态不确定
不能直接取消这个标签。顶层必须学会用预测的破译状态维持行为，而不是在独立 Q
数据准入时额外加状态门槛。

“顶层指导动作”需要有代码和模型证据：phase、目标、steering、decoding 的预测
作为 planner 条件；固定图像，分别改变这些预测，检查相应动作是否变化；训练后
还要报告阶段/状态正确率及联合行为，不能只打印一个 phase 名称声称已指导动作。
如跳过预测条件后正确率不变，应查旁路是否绕过顶层；没有这种测量前不声称层级已成立。

**当前实现差距**：旧 m28 的 `planner_from_predicted_state` 已消费 intent/subgoal、
prompt/reachable、camera phase/target/steering/path，但 `GroundingOutput` 没有
decoding 输出；旧 camera phase 四类也不是这里的完整子任务。CSV 之前还不能填写
当前破译状态，已新增 decoding/evidence 列和因果校验。当前 `facts.decoding`
可导出为有 mask 的监督，但新状态头/phase 头和顶层执行反馈仍待模型/runtime 迁移。
旧 `DecodeStateTracker` 从 Q 推测 active 是事件回放启发式，不能充当视觉破译真值。

完整顶层训练需有 `decoding=true` 与 false/unknown 的真实可观察片段，以及
maintain_decode 的动作示范。当前四条记录能训练 prompt→Q，但仅有三种矩形类别
不能自动产生“正在破译”标签；有证据的帧标注，尾部确实看不出来则 unknown。
不废弃已经完成的 Q 标注，也不把未知自动标为 false。

### 0.13 M29：状态引导动作网络（State-Guided Action Network）

为使“上层预测状态实际影响下层动作”成为可检查的结构，当前新架构命名为
**M29 State-Guided Action Network（SGAN，状态引导动作网络）**，代码位于
`idv_agent/model/state_guided_action.py`。

```text
Qwen frozen visual features + real capture times
                 │
                 ▼
        temporal visual state s
          ├─ facts: visibility / bbox / interact_prompt / decoding
          ├─ top-level context: s + execution feedback
          │       └─ phase / steering / path
          │                └─ soft predicted beliefs
          │                           └─ navigation: move / camera
          └─ latest-frame prompt_q(s_latest) ─────────── Q / NO_Q
```

M29 的硬结构约束是：`navigate_from_beliefs(beliefs)` 的输入只有预测状态向量，
不接原始图像、GRU 隐变量或标注真值；因此删除 phase/steering/path 后，下层动作
必须可以被干预测试观察到变化。顶层仍可使用视觉状态上下文判断障碍和路径，
但导航输出不能从这条上下文旁路读取原始视觉特征。

Q 的快速支路只读最新视觉特征，输出与 `facts.interact_prompt` 相同语义的 Q logit；
它不读 phase、decoding、过去 Q 或人类 replay 时刻，所以“有提示→Q、无提示→NO_Q、
短时连续 Q”可以在顶层较慢时独立工作。Q 与导航动作在 `M29CommandMerger` 汇合，
一条命令发送路径把实际 `submitted` 反馈写回下一次顶层输入；`submitted` 不等于
游戏已进入破译，后者仍由视觉 `decoding` 事实判断。

M29 checkpoint schema 为 `m29.state_guided_action.v2`，只接受：固定 task=decipher、
200 ms action、码本 `[-110,-25,0,25,110]`、`interact_prompt_to_q.v1`、
`hierarchy=predicted_beliefs_only` 和 `state_bottleneck=discrete_straight_through_v1`。
visibility/decoding/prompt/phase/steering/path 在下层前向中是离散语义值，训练时通过
straight-through 保留动作损失到状态头的梯度；target/prompt bbox 保留连续值。
旧 M29 v1、m28/v5 checkpoint 全部 fail-closed。

`train_m29 --task q` 训练 prompt Q 与 prompt bbox；`--task full` 必须使用
`--init-checkpoint` 继承 Q 阶段，并可把全帧 Q v2 与 full V6 文件同时传给 `--data`。
相同 endpoint ID 经 Q、图像一致性检查后只保留 full 行。full 准入检查五阶段、

## 2. VLA 原生动作块（当前主线）

VLA 不受上面的 20 类离散动作约束。模型直接读取连续画面序列、任务指令和
历史动作，预测短动作块；旧 `samples.jsonl`/`ActionCategory` 仅作为教师数据或最终
执行器适配，不是 VLA 的输入契约。

当前训练主线为 v5；v3/v4 仅保留用于历史数据兼容。任何新 ACT 训练只能消费
通过第 7 节「训练集准入审计」的 v5 数据与训练期 sidecar 标签。

固定 v5 形状：

每条样本顶层必须带 `mode`，并在任务文本前注入对应 token：`<mode:standard>`、
`<mode:joint_hunt>` 或 `<mode:blackjack>`。三种模式共享本动作空间；差异由模式
LoRA 学习，而不是复制三套动作头。

```text
observations.frames       v3 为 3 帧；v4/v5 为 3..8 帧（当前 v5 固定 8）
action_chunk              4 步
每步 duration_frames      v5 固定 6（约 0.2 秒@30 FPS）
```

每个动作块元素采用九方向移动、每轴五档相机桶和六个独立按键位：

```json
{
  "mode": "standard",
  "move_dir": 1,
  "camera_dx": -2,
  "camera_dy": 0,
  "buttons": [1, 0, 0, 0, 0, 0],
  "duration_frames": 6
}
```

`move_dir` 取值为 `0..8`：`stop/north/northeast/east/southeast/south/southwest/west/northwest`。
`camera_dx/camera_dy` 取值为 `-2..2` 五档。v5 每个动作块还必须保留
`camera_dx_px/camera_dy_px`，它们是该 6 帧宏动作的 Raw Input 净像素位移；校验器会
验证像素值与桶一致。桶边界和执行代表值只定义在 `idv_agent/vla/action_chunk.py`：
`[-12,12]→0`、`(12,67.5]→1`、`>67.5→2`（负方向对称），代表值为
`-2/-1/0/1/2 → -110/-25/0/25/110 px`。训练标签和 ACT 执行器共用这张表。
这是相邻执行代表值的中点划分：`0↔25` 的边界为 `12.5`（按整数 Raw Input
写为 12/13），`25↔110` 的边界为 `67.5`（按整数写为 67/68）。因此 `±13..±67`
属于细转 `±1`，而非粗转 `±2`。
`buttons` 顺序固定为
`interact/vault/item/heal/sprint/crouch`。其中 `interact` 是一次性 Q 触发脉冲：只有
包含 Q 按下边沿的宏步为 `1`，自动破译后续的 `INTERACT_HOLD` 状态不重复产生交互
按键；其余按键位保持 0/1 持续状态语义。ACT 执行器将 `interact=1` 发送为一次
`press + release`，不会把 Q 放入持续按键集合。

相机增量的聚合约定：`per_frame_actions.csv` 中的 `cam_dx_px/cam_dy_px` 是逐帧 Raw Input
像素增量，
构建一个 v5 宏动作（固定 6 帧）时必须先求有符号累积位移，再量化到五档；不能取帧均值，
否则正常的微调会被压回 `0` 桶。移动方向与相机桶是并行输出，执行器可以同时发送
（例如 `W + camera_dx=1`），从而表达“转视角改变后续行进朝向”；移动键本身仍保持
相机相对语义，不把它误解为世界坐标方向。若一个宏动作内发生左右反转，单个桶无法
表达中间序列，应缩短 `macro_frames` 或在后续版本引入子步动作。

v5 的 `observations.history_actions` 是最近 8 个已经完成的 6 帧宏动作摘要，而不是单帧
采样；其字段布局与 ACT 执行器的 72 维 history 完全一致。canonical v5 使用 24 帧
anchor 间隔（等于 4×6 帧未来标签窗口），确保所有未来帧都有且仅有一个默认标签窗口。
冷启动时在 8 个完整历史宏
动作形成前，history 固定为 8 个零动作；视觉窗口达到 8 帧后即可产生首个 v5 样本，
不因等待 history 而丢失开局早期交互标签。

这种设计覆盖对角移动，又避免把交互动作编码进导航类别。YOLO bbox、状态机和几何量
放在可选 `auxiliary`，模型在缺少这些字段时仍必须能够推理。
完整校验和构建实现位于 `idv_agent/vla/action_chunk.py` 与
`idv_agent/scripts/build_vla_chunks.py`，产物为 `vla_chunks.jsonl`。

快慢 VLA 的时序窗口、context 融合、特征缓存和慢标签采样协议见
[docs/15-快慢VLA接口与时序缓存协议.md](15-快慢VLA接口与时序缓存协议.md)。该协议将运行时
缓存上限固定为 8 帧；这里的 v3 `observations.frames` 历史字段是数据兼容字段，后续
构建器会增加 `slow_label` 与 `loss_mask`，不能由训练器临时推断。

### 2.1 帧-动作时间对齐协议（强制）

VLA 样本采用因果未来标签，禁止把“当前正在发生的动作”直接当作当前帧的
决策标签。`anchor_frame` 表示最后一张输入画面；动作块从
`anchor_frame + action_delay_frames + 1` 开始。这里 `action_delay_frames` 的语义是“观测结束
后跳过的帧数”，不是总帧间隔；默认值 1 表示跳过 `anchor+1`，首个动作帧为 `anchor+2`。
这样至少隔开一帧（约 33ms@30FPS），避免捕获、推理和写盘延迟造成标签泄漏。

```text
输入帧:       t-6, t-3, t       （观测结束 = t）
延迟保护:                         t+1
动作块标签:                         t+2 ... t+25
```

录制时所有帧和输入事件必须使用同一 `perf_counter_ns` 时钟。构建器优先使用
`frame_timestamps.csv`，再将事件按时间窗口聚合到未来动作块；不得仅凭文件名或
线性帧号假定同步。若采集/推理延迟改变，应重新测量并调整 `action_delay_frames`，
同时在 `alignment` 字段记录实际值。

### 2.2 VLA v3 意图列表（任务级）

意图是短时任务约束，不是每帧按键类别；每条样本可只标一个主意图：

| 意图 | 含义 |
|---|---|
| `search_cipher` | 搜索尚未锁定的密码机 |
| `align_cipher` | 调整视角/位置让目标进入可接近方向 |
| `approach_cipher` | 向目标持续靠近 |
| `start_decode` | 已出现交互提示，准备按 Q |
| `decode` | 保持破译，包含校准等待 |
| `recover_target` | 目标暂时丢失，重新观察/搜索 |
| `avoid_obstacle` | 遇障碍进行短时绕行或脱困 |
| `stop_safety` | 不确定、异常或等待人工确认 |

意图字段只表达“当前要完成什么”，动作块字段表达“接下来怎么做”；二者不互相

### 2.3 对外部建议的选择性合并

已参考 `keymap.json`、`actions.md`、`intents.md`，但没有直接复制文件或实现。最终取舍：

| 建议 | 决策 | 原因 |
|---|---|---|
| WASD 合成八方向移动 | 采用，连同 `stop` 组成九方向 | 对角移动不能用左右/前进均值替代，否则标签含义会模糊 |
| 相机每轴离散桶 | 采用五档 `-2..2` | 第一版更容易学习、推理更快；原始鼠标增量留在辅助字段以便重分桶 |
| 六个开关键位 | 采用 `interact/vault/item/heal/sprint/crouch` | 低频键先不进主头，但原始事件始终保留，后续可扩展 |
| 八个顶层意图 | 采用 `decipher/kite/rescue/rotate/travel/search/gate/idle` | 意图表达任务阶段，子意图不强制注入，降低标注成本 |
| 固定键位映射 | 仅作为默认参考 | 必须以当前游戏内实际键位和角色配置为准；尤其 F 键语义不能盲目覆盖 |
| 每帧即时动作标签 | 不采用 | 改用因果未来动作块，并记录真实时间戳和延迟 |

因此，VLA 主头不输出自然语言动作字符串，也不依赖旧 20 类 `ActionCategory`；最终
执行器再把九方向和按键位映射为实际键鼠事件。老师建议中的低频键会保留在原始
`events.csv`，而不是丢弃，以便未来扩展动作头。

```
held_keys, text_action, decode_calibration, decode_start
```

## 6. 破译状态机语义（P2 修复点）

第五人格按一次 Q 即自动破译（无后续按键），需要隐式状态识别（`labels/state_machine.py`）：

1. Q press（always-enter）：进入破译态，重置起始时间。
2. WASD / SKILL / ITEM / MAP / EMOTE press：退出破译（做别的去了）。
3. **Space press during decode = 校准**（不是真翻窗）。新项目在 `FrameState` 增加 `decode_calibration` 标记帧——`cat = INTERACT_HOLD` 但 `flag = calibration`，供后续视觉辅助标注校准样本（补救 P2，不必重录即可能学到校准）。
4. 破译 > `max_decode_duration_s`（90s 默认）：强制退出（Q 误触保护）。
5. 破译中 NOOP/LOOK/VAULT 帧重写为 INTERACT_HOLD（语义 = 破译中）。该状态只用于
   识别持续破译，不等价于再次按 Q；逐帧提取同时写出 `decode_start` 边沿字段，v5
   宏动作只把该边沿聚合为一次 `buttons[0]` 脉冲。

## 7. v5 MVP 数据准备与标签契约（当前唯一主线）

本节是从采集到可训练数据的唯一顺序。`data/new_vla_raw_sessions` 是只读原始
证据；所有 JSONL、CSV、标注池和审计报告都是可重建派生物。不得以手改
`per_frame_actions.csv` 或覆盖 raw 文件的方式修标签。

```text
官方自定义剧本 / 训练营的人类演示
  │ record_vla（frames + 同一 perf_counter_ns 时钟的 events / Raw Input mouse）
  ▼
validate_vla_raw
  ▼
人工 intent_segments（只标顶层时间片段） + frame_states（按需）
  ▼
extract_session（逐帧按键状态 + cam_dx_px/cam_dy_px + decode_start）
  ▼
build_vla_chunks / train_vla_chunks_v5（8 帧观测 → 因果未来 4×6 帧 chunk）
  ▼
prepare_mvp_data --event-centered（整 session train/val；Q 样本替换重叠 periodic 样本）
  ├─ ACT 主标签：slow_label + action_chunk[0..3]
  ├─ grounding sidecar：画面中密码机/Q 提示的事实
  └─ camera-control sidecar：人在该画面下的意图性镜头决策
  ▼
audit_mvp_training_data（训练集准入） → train_vla
```

### 7.1 原始采集与逐帧行为标签

每一个原始 session 必须有：

```text
frames/                    连续帧，文件名从 00000000.jpg 连续递增
frame_timestamps.csv       每帧 capture 的 perf_counter_ns
events.csv                 键盘/鼠标 down/up 事件，同一时钟
mouse_deltas.csv           Raw Input 相对 dx/dy，同一时钟
meta.json                  mode、任务、FPS、录制范围、action_delay_frames=1
```

`record_vla` 只采集，绝不注入输入；先运行：

```powershell
python -m idv_agent.scripts.validate_vla_raw <session>
```

`extract_session` 对每个保存帧的时间区间 `(prev_frame_ts, frame_ts]` 回放输入：

| `per_frame_actions.csv` 字段 | 唯一来源 | 作用 |
|---|---|---|
| `move_x/move_y`、`held_keys` | events.csv 的按住状态 | 宏动作移动和按键标签 |
| `cam_dx_px/cam_dy_px` | mouse_deltas.csv 的区间有符号和 | v5 相机标签的唯一物理来源 |
| `cam_dx/cam_dy` | 像素值除以旧 `cam_pixel_scale` | 仅历史 v3/v4 兼容；v5 不使用它分桶 |
| `decode_start` | Q 按下边沿 + DecodeStateTracker | v5 `buttons[0]` 的一次性 Q 脉冲 |
| `decode_calibration` | 破译中 Space | 状态/标注辅助；不是重复 Q |

录制开始后的“看图上似乎该转、但人尚未输入”的空白帧仍如实保留为 `replay=0`；
它不能被伪改成转向标签。若它不应成为决策训练样本，应由 chunk 选择/质量规则排除，
而不是篡改 Raw Input 行为证据。

### 7.2 人工慢标签与 v5 因果 action chunk

人工只编辑 `intent_segments.csv/jsonl` 的连续区间：

```text
start_frame, end_frame, intent, segment_id
```

MVP 保留 `travel` 和 `decipher`；`subgoal` 由固定 `subgoal.v1` 规则派生，不能作为
第二套人工动作标签。v5 chunk 的固定协议为：

| 项目 | 约定 |
|---|---|
| 视觉观测 | 8 帧，帧距 3；最后一帧是 `observation_end_frame` |
| action delay | 1 帧；h0 从 `observation_end_frame + 2` 开始 |
| 行为目标 | 4 个连续宏动作，每步固定 6 帧；部署/训练因果执行只消费 h0 |
| 周期采样 | anchor stride 24，避免相邻 periodic 样本的未来窗口重叠 |
| Q 事件 | event-centered anchor=`q_frame-2`，h0 从 Q 帧开始；同未来窗 periodic 行删除 |
| Q 决策慢标签 | event-centered 行的顶层 `slow_label` 取 Q 决策帧的 `decipher/start_decoding`，观测历史帧仍保留真实历史语义 |

`train_vla_chunks_v5` 会逐记录验证时间顺序、帧覆盖、8 帧/8 history、每步 6 帧、
像素净位移与 bucket 一致性，并写 `vla_chunks_v5.audit.json`。单 session audit 通过
不等于可训练；还必须通过第 7.5 节的全数据准入审计。

### 7.3 标签层 1：行为复刻标签（永不人工覆盖）

v5 `action_chunk[h]` 是人类演示在未来 6 帧实际执行的复刻标签：

```text
move_dir, camera_dx/camera_dy, camera_dx_px/camera_dy_px,
buttons[interact/vault/item/heal/sprint/crouch], duration_frames=6
```

相机必须先对 6 帧 Raw Input 求有符号净位移、后分桶：

| 净像素范围 | bucket | 执行器代表像素 |
|---|---:|---:|
| `[-12, 12]` | `0` | `0` |
| `[-67.5, -13]` | `-1` | `-25` |
| `<= -68` | `-2` | `-110` |
| `[13, 67.5]` | `+1` | `+25` |
| `>= 68` | `+2` | `+110` |

边界与执行代表值只来自 `idv_agent/vla/action_chunk.py` 的
`CAMERA_BUCKET_EDGES_PX` / `CAMERA_BUCKET_COMMAND_PX`；训练、离线评估和执行器
不得各自维护另一套阈值。`replay_camera_dx/dy` 是对 h0 行为标签的审计副本，
不是 `desired_turn_*` 的替代物。

### 7.4 标签层 2：训练期视觉事实（grounding sidecar）

`data/mvp_act_grounding_pool_v1/act_grounding_annotations.jsonl` 的每行对应原始帧，
来自三个 YOLO 类 `cipher_visible/cipher_highlight/interact_prompt`。它不是 runtime
检测依赖，也不要求每一行都恰好是 ACT decision endpoint；Dataset 只会精确匹配
`(session, observation_end_frame)` 的行，其余 Q 邻域帧保留为标注覆盖证据。

| 字段 | 语义与不变量 |
|---|---|
| `cipher_bbox_xyxy_norm` | 可见密码机（优先）或高亮的 `[x1,y1,x2,y2]`；无机器为 `null` |
| `target_side` | `left/center/right/none`；无 bbox 必须为 `none` |
| `interact_prompt` | Q 交互 UI 是否出现；为 1 时密码机一定可见 |
| `cipher_reachable` | 当前可接近/交互；prompt=1 时必须为 1 |

角色遮挡密码机但仍出现 Q 提示时，仍标记密码机可见；`target_side` 以
`interact_prompt` 框中心为准。没有标注不等于负样本：Dataset 将其 `grounding_mask=0`。

### 7.5 标签层 3：训练期镜头控制语义（camera-control sidecar）

这层解决“画面相近但 replay mouse 不同”的路径/避障混杂。文件为：

```text
camera_control_train.v2.rebucket675.annotated.jsonl
camera_control_val.v2.rebucket675.annotated.jsonl
```

每行必须精确匹配一个 canonical v5 的 `(session, observation_end_frame)`，并保存但不
修改 h0 `replay_camera_dx/dy`。人工填写的是：

| 字段 | 枚举 | 含义 |
|---|---|---|
| `camera_control_phase` | `search/target_acquire/target_align/hold` | 当前在扫视、首次获取、对齐、还是保持 |
| `camera_target_id` | `target_cipher/other_visible/none` | 画面内可见对象是否为导航目标 |
| `camera_steering_mode` | `target_center/path_follow/search_sweep/hold` | 镜头服务于中心化、绕行路线、扫视或停止 |
| `path_strategy` | `direct/detour_left/detour_right/unknown` | 仅 `path_follow` 可填前三项；其他必须 `unknown` |
| `desired_turn_dx/dy` | `-2..2` | 在当前视觉与路径状态下应执行的单步镜头意图 |
| `replay_camera_dx/dy` | `-2..2` | immutable 的 h0 行为复刻证据 |

`desired_turn_*` 可以等于 replay（大量直行搜索/获取确实如此），但绕障、保持路线、
录制延迟或无输入空白时可以不同。它不是“把机器拉到屏幕中心”的固定规则，而是人工对
当前阶段和路线的可执行判断。部署只使用模型预测的 control logits；绝不读取 sidecar。

标注文件必须先通过：

```powershell
python -m idv_agent.scripts.prepare_camera_control_annotations validate --input <file>
```

### 7.6 canonical MVP 数据与训练准入

当前唯一 MVP 训练根目录：

```text
data/mvp_vla_v5_event_centered_decision_label_v3_rebucket675/
  train/  732 chunks, 79 sessions
  val/    182 chunks, 20 sessions
  manifest.json
  class_balance_h0_rebucket675.json
```

它从 `data/new_vla_raw_sessions` 的 99 个 session 派生，按整个 session 划分、零重叠；
仅保留 `travel/decipher`。每次训练前运行：

```powershell
python -m idv_agent.scripts.audit_mvp_training_data `
  --dataset data/mvp_vla_v5_event_centered_decision_label_v3_rebucket675 `
  --grounding-annotations data/mvp_act_grounding_pool_v1/act_grounding_annotations.jsonl `
  --camera-control-train data/mvp_act_grounding_pool_v1/camera_control_train.v2.rebucket675.annotated.jsonl `
  --camera-control-val data/mvp_act_grounding_pool_v1/camera_control_val.v2.rebucket675.annotated.jsonl `
  --class-balance data/mvp_vla_v5_event_centered_decision_label_v3_rebucket675/class_balance_h0_rebucket675.json `
  --output reports/mvp_v5_rebucket675_training_data_audit.json
```

准入审计 fail-closed 验证：v5 schema/时间对齐、train/val session 零重叠、grounding
标注属于正确 split、control 标注属于正确 split 且精确附着到 decision endpoint、
control 的 replay 与 canonical h0 bucket 一致、以及 class weight 的统计范围确为 h0
训练标签。若 raw session 有重新采集或重建，再加 `--validate-raw-sessions`。
