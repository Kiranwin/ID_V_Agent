# 14 · VG 标注格式与消费路径

本项目只维护一套人工框标注：YOLO `labels/*.txt`；另外维护一份逐帧状态标注
`frame_states.jsonl`。VG 训练样本不是第二套手工框，而是从这两份标注可重复生成的
派生数据。这样修改框或状态时，检测头和视觉语言训练都能同步更新。

## 1. 一条标注、两个消费者

```text
原始帧
  ├─ YOLO 人工框（物体/视觉证据）
  │    └─ train_yolo.py → YOLO 检测头 → 实时 bbox
  │
  └─ frame_states.jsonl（每帧状态）
       └─ convert_yolo_to_vg.py
            ├─ vg_annotations.jsonl（框 + state + intent_hint）
            └─ vg_grounding.jsonl（grounding / presence 问答）
                 └─ WK/VG 辅助训练 → Qwen/VLA 空间理解
```

`vla_chunks.jsonl` 是 ACT 动作块的监督数据，仍由原始事件和时间戳生成；它不依赖
YOLO 框，也不能用 VG 问答替代动作标签。后续可以把 VG 框作为 `auxiliary` 加入 ACT
样本，但不能让 ACT 训练必须依赖 YOLO。

## 2. YOLO 人工标注协议

YOLO 当前三类固定为：

| id | 类别 | 语义 |
|---:|---|---|
| 0 | `cipher_visible` | 视野中实际可见的密码机几何部分 |
| 1 | `cipher_highlight` | 被遮挡时可见的黄色密码机高亮/信标 |
| 2 | `interact_prompt` | 扳手和 `[Q]` 交互提示 |
帧状态不再是 YOLO 类别，单独从 `frame_states.jsonl` 标注：

| 状态 | 含义 | 对齐的 intents.md 顶层意图提示 |
|---|---|---|
| `decoding` | 已进入破译状态，包含校准等待 | `decipher` |
| `idle` | 停止/观察/没有持续移动 | `idle` |
| `walking` | 正在前进、转向或移动接近目标 | `travel` |
| `chased` | 正在被监管者追击或执行牵制 | `kite` |

`intent_hint` 优先来自人工 `intent_segments.csv/jsonl`，并记录 `intent_source`；没有人工
分段时才回退为由状态派生的弱提示。它不取代 ACT 样本中的 `slow_label.intent`。

标注仍使用标准 YOLO 行：

```text
class_id x_center y_center width height
```

三个类别的坐标归一化到 `0..1`。只框实际看见的区域，不臆测被墙遮挡的机器主体。
黄色高亮是密码机的可见状态，不是第二个场景物体；若同一帧既有高亮又有扳手提示，
可以同时存在两行不同类别。

## 3. 帧级状态标注

帧状态默认由事件流自动推断，不要求人工逐帧填写。运行：

```powershell
python -m idv_agent.scripts.infer_frame_states `
  data/vg_cipher_20260901_105143 `
  --repo-root . `
  --output data/vg_cipher_20260901_105143/frame_states.jsonl
```

推断器读取 manifest 对应 raw session 的 `events.csv`（也支持 `events.jsonl`）、
`frame_timestamps.csv`、`mouse_deltas.csv` 和 YOLO `interact_prompt` 框：

- `decoding`：Q 在该帧按住，且该帧有 `interact_prompt` 框；
- `walking`：有 W/A/S/D 按住，或有其它鼠标/键盘活动，且不是 `decoding`；
- `idle`：没有输入活动；
- `chased`：默认关闭，追击帧并入 `walking`。

可用 `--chased-heuristic` 启用第一版近似（持续 WASD + 连续视角变化），但这只是候选
标签，监管者对象检测上线后应重新生成。输出中的 `evidence` 保存每帧的推断依据，
方便抽查和修正。默认拒绝覆盖已有状态文件，确认重建才加 `--overwrite`。

创建模板：

```powershell
python -m idv_agent.scripts.init_frame_states \
  data/vg_cipher_20260901_105143
```

模板文件：

```text
data/vg_cipher_20260901_105143/frame_states.jsonl
```

如果自动推断结果需要人工抽查，直接编辑每行的 `state` 字段：

```json
{"session":"20260901_105143","frame":250,"state":"walking"}
```

最终每一行必须且只能是 `decoding`、`idle`、`walking`、`chased` 之一；不能留空，
不能使用 `unknown`。状态是整帧标签，不画框：

- `decoding`：按 Q 后已进入破译，包含破译 UI 或校准等待；
- `idle`：角色停止、观察或无明确移动；
- `walking`：角色正在走、转视角接近目标或绕行；
- `chased`：有明确追击/牵制场景证据，不能仅凭“正在移动”判断。

单标签冲突时按以下优先级裁决：`chased` > `decoding` > `walking` > `idle`。例如正在
移动但明确受到监管者追击，标 `chased`；破译中的校准或短暂停顿仍标 `decoding`；
只有视角扫视、没有移动且不在破译/追击时标 `idle`。

当前第一局主要是 `walking`、`decoding` 和少量 `idle`；没有可靠追击证据的帧不要标
`chased`，应按实际状态标 `walking` 或 `idle`。若这局没有追击片段，不需要强行制造
`chased` 样本，后续专门录制补充。

## 3. 转换产物

运行：

```powershell
python -m idv_agent.scripts.convert_yolo_to_vg \
  data/vg_cipher_20260901_105143 \
  --intent-segments data/vla_raw_sessions/20260901_105143/intent_segments.csv
```

默认生成：

```text
data/vg_cipher_20260901_105143/vg_annotations.jsonl
data/vg_cipher_20260901_105143/vg_grounding.jsonl
```

状态生成后可额外生成帧级 QA：

```powershell
python -m idv_agent.scripts.generate_frame_qa `
  data/vg_cipher_20260901_105143 `
  --annotations data/vg_cipher_20260901_105143/vg_annotations.jsonl `
  --states data/vg_cipher_20260901_105143/frame_states.jsonl `
  --meta data/vg_cipher_20260901_105143/meta.json `
  --output data/vg_cipher_20260901_105143/frame_qa.jsonl
```

`--intent-segments` 应指向人工确认的 CSV/JSONL；也可用 `--intent search` 显式覆盖。
没有分段或覆盖不到该帧时，生成器回退到 `intent_hint`，并在每条样本写入 `intent_source`。
每帧固定生成 4 条模板 QA：状态、密码机存在性、密码机高亮
属性和当前意图，全部由已有标签派生，不新增人工标注。

### 3.1 `vg_annotations.jsonl`

每张图片一条结构化记录，是 VG 的中间真源。每帧同时保留 `state` 和由它派生的
`intent_hint`；每个对象同时保留：

- `bbox_xyxy_norm`：归一化 `[x1,y1,x2,y2]`；
- `bbox_xyxy_px`：原图像素坐标；
- `source_class`：原始 YOLO 类别；
- `label`：派生语义标签；
- `visibility`；对象不再携带帧级 `state`。

示例：

```json
{
  "schema_version": "vg.grounding.v2",
  "image": "data/vg_cipher_20260901_105143/images/train/20260901_105143_00000250.jpg",
  "source_session": "20260901_105143",
  "source_frame": 250,
  "split": "train",
  "state": "walking",
  "intent_hint": "travel",
  "objects": [
    {
      "label": "cipher_machine",
      "source_class": "cipher_visible",
      "bbox_xyxy_norm": [0.54, 0.45, 0.69, 0.68],
      "bbox_xyxy_px": [720.0, 337.5, 920.0, 510.0],
      "visibility": "visible"
    }
  ]
}
```

这是模型无关格式。以后 Qwen 需要特殊 box token、整数 0..1000 坐标或检测头张量时，
都从这里渲染，不重新标图。

### 3.2 `vg_grounding.jsonl`

这是给视觉语言训练器消费的派生问答。典型样本：

```json
{
  "task": "grounding_qa",
  "image": "...jpg",
  "question": "密码机在哪里？",
  "answer": "密码机位于画面右侧，框坐标为 [0.5400, 0.4500, 0.6900, 0.6800]。",
  "target": {
    "label": "cipher_machine",
    "bbox_xyxy_norm": [0.54, 0.45, 0.69, 0.68],
    "visibility": "visible"
  },
  "objects": ["...同图全部对象..."],
  "source_session": "20260901_105143",
  "source_frame": 250,
  "split": "train"
}
```

生成器只生成 grounding/presence 问答；状态问答统一由 `frame_qa.jsonl` 提供，避免重复。
每条样本仍保留帧级 `state` 和 `intent_hint`。
`decoding` 不再通过一个 UI 框表达。
文本中的坐标只是可读渲染；训练器应优先读取 `target` 的结构化坐标，避免语言格式变化
影响监督。

## 4. 到底训练检测头还是 grounding 问答？

两者都可以，但用途不同：

| 路径 | 训练输入 | 输出 | 用途 |
|---|---|---|---|
| YOLO 检测头 | 图片 + YOLO txt | 类别和 bbox | 快速、稳定的实时检测；规则兜底和安全门控 |
| VG grounding | 图片 + 问题 + `target` 坐标 | 空间问答/坐标 | Qwen/VLA 的视觉语言和空间 grounding 后训练 |
| ACT | 多帧 + 指令 + 历史动作 | 未来动作 chunk | 最终 VLA 控制；不直接读取 YOLO |

第一阶段建议先训练 YOLO 检测头，因为它能独立验证框质量和实时延迟；随后用相同框
派生 VG 样本做 Qwen/VLA 的视觉语言辅助训练。VG 的 grounding 准确率不能替代实机
动作成功率。

## 5. 标注完成后的命令顺序

```powershell
# 1. 创建并填写帧状态
python -m idv_agent.scripts.init_frame_states \
  data/vg_cipher_20260901_105143

# 2. 检查 YOLO 标签和状态文件（转换器会强校验）
#    确认类别、坐标、空标签和图片一一对应；每帧 state 必须完整

# 3. 直接训练/评估检测头
python -m idv_agent.scripts.train_yolo \
  --data data/vg_cipher_20260901_105143/dataset.yaml

# 4. 从同一批 YOLO 框 + 帧状态生成 VG 中间标注和问答
python -m idv_agent.scripts.convert_yolo_to_vg \
  data/vg_cipher_20260901_105143

# 5. 检查 raw session 和 ACT action chunks
python -m idv_agent.scripts.validate_vla_raw \
  data/vla_raw_sessions/20260901_105143
```

只有补充多个 session 后，才按 session 划分 train/val/test。当前单 session 的 `train`
仅是标注池，不能用来报告泛化性能。

## 6. 当前不需要做的事

- 不要为 VG 再画一套不同坐标的框；
- 不要把黄色高亮框成整台“想象中的”密码机；
- 不要把 `interact_prompt` 当作密码机主体框；
- 不要把 `decoding` 画成 YOLO 框；它是整帧状态；
- 没有人工分段时才不要把 `walking` 自动等同于所有导航意图；此时 `intent_hint` 才是弱提示；
- 不要把 YOLO 检测结果拼进 ACT 的必需输入；
- 不要在未确认 Qwen box token 渲染规则前，把字符串格式写死成某个模型的特殊 token。

## 7. ACT 相机 grounding 标注池（MVP）

当 ACT 的相机标签来自 Raw Input 回放时，标签只说明“人类转了多少”，并不说明当时画面里的
密码机在何处。对当前 canonical
`mvp_vla_v5_event_centered_decision_label_v3_rebucket675`，用以下命令创建同 session、
已按 canonical split 隔离的高价值标注副本：

```powershell
python -m idv_agent.scripts.prepare_act_grounding_pool `
  data/mvp_vla_v5_event_centered_decision_label_v3_rebucket675 `
  --output data/mvp_act_grounding_pool_v1 `
  --camera-per-bucket 8 `
  --q-radius-frames 6
```

该命令拒绝覆盖非空输出目录，保护人工标注。导出的 `images/<split>/`、`labels/<split>/` 和
`dataset.yaml` 与本章 YOLO/X-AnyLabeling 工作流一致：密码机实体/高亮/交互提示仍仅使用三个
YOLO 类。打开图片同名 `.json` 标注后，运行：

```powershell
python -m idv_agent.scripts.convert_anylabeling_to_yolo `
  data/mvp_act_grounding_pool_v1
```

还必须编辑每帧一条的 `act_grounding_annotations.jsonl`，填写：

| 字段 | 填写规则 |
|---|---|
| `cipher_bbox_xyxy_norm` | 有确认密码机/高亮时填 `[x1,y1,x2,y2]`；确实没有时填 `null` |
| `cipher_reachable` | `1` 只表示此刻可通过接近/交互处理；无目标框时必须为 `0` |
| `target_side` | 有目标框填 `left`/`center`/`right`；无框必须为 `none` |
| `interact_prompt` | 当前帧出现可按 Q 的 UI 提示则填 `1`，否则填 `0` |

如果图片已通过 X-AnyLabeling 完成，且“没有同名 JSON”被确认表示该帧没有可见密码机，
可以先将 JSON 转为 YOLO，再从 YOLO 自动写入以上辅助字段：

```powershell
python -m idv_agent.scripts.convert_anylabeling_to_yolo `
  data/mvp_act_grounding_pool_v1

python -m idv_agent.scripts.prepare_act_grounding_pool `
  data/mvp_act_grounding_pool_v1 `
  --populate-from-yolo
```

自动生成前会创建一次 `act_grounding_annotations.before_yolo_auto.jsonl` 备份，若该备份已存在
则拒绝再次覆盖。选择规则是 `cipher_visible` 优先、否则取 `cipher_highlight` 的最大可见框；没有
`interact_prompt` 时由该框中心自动产生 `target_side`。存在 `interact_prompt` 时，密码机必须同时
具有 `cipher_visible` 或 `cipher_highlight` 框；`cipher_reachable=1`，且 `target_side` **必须以提示框
中心为准**，不以被角色部分遮挡的机器框为准。转换器和完整性校验都会拒绝“有 Q 提示却没有密码机框”。
没有任何密码机框和提示框时，才标为 `bbox=null`、`target_side=none`、`cipher_reachable=0`、
`interact_prompt=0`。

训练数据制作前必须 fail-closed 校验完整性：

```powershell
python -m idv_agent.scripts.prepare_act_grounding_pool `
  data/mvp_act_grounding_pool_v1 `
  --validate-annotations
```

这个 sidecar 是训练期真值，不能成为部署的实时输入。ACT 的视觉辅助头学习预测它；最终动作头只接收
图像、指令、模式和既定的历史动作输入。

## 8. Camera-control 语义标注：与 replay 行为标签分层

grounding 回答“画面中有什么”，不能消除“同一机器位置、但人因绕障而转镜头”的
行为混杂。于是另有训练期 control sidecar，当前已完成：

```text
data/mvp_act_grounding_pool_v1/camera_control_train.v2.rebucket675.annotated.jsonl  # 48
data/mvp_act_grounding_pool_v1/camera_control_val.v2.rebucket675.annotated.jsonl    # 46
```

这些行只对应 ACT 的 `observation_end_frame`，不是普通 Q 邻域图像。每个 control row
保留 immutable `replay_camera_dx/dy`，它必须等于 canonical h0 的 Raw Input bucket；
人工不能把 replay 改成主观正确答案。新增字段的填写契约如下：

| 字段 | 可填值 | 填写含义 |
|---|---|---|
| `camera_control_phase` | `search` / `target_acquire` / `target_align` / `hold` | 当前镜头控制阶段 |
| `camera_target_id` | `target_cipher` / `other_visible` / `none` | 可见对象是不是本次导航目标 |
| `camera_steering_mode` | `target_center` / `path_follow` / `search_sweep` / `hold` | 转镜头是居中、配合路线、扫视还是停止 |
| `path_strategy` | `direct` / `detour_left` / `detour_right` / `unknown` | 仅 `path_follow` 时使用 direct/detour；其他必须 unknown |
| `desired_turn_dx/dy` | 每轴 `-2..2` | 对当前视觉和路径状态的下一步镜头意图 |

示例：密码机刚在右侧出现、尚不可达，正常向右获取目标：

```json
{
  "replay_camera_dx": 2,
  "camera_control_phase": "target_acquire",
  "camera_target_id": "target_cipher",
  "camera_steering_mode": "target_center",
  "path_strategy": "unknown",
  "desired_turn_dx": 2,
  "desired_turn_dy": 0
}
```

绕障时，即使密码机未居中，镜头可能服务于 `path_follow + detour_left/right`；此时
`desired_turn` 可以不同于 replay。反之，录制刚开始尚未输入的空白帧不能凭画面补写
replay；若被选作 control 行，填写的是当前意图，保留原 replay=0 供模型区分。

每次增标必须先生成独立 pending 副本、完成后校验，不能覆盖原始/canonical 数据：

```powershell
python -m idv_agent.scripts.prepare_camera_control_annotations prepare `
  --data data/mvp_vla_v5_event_centered_decision_label_v3_rebucket675/train `
  --grounding-annotations data/mvp_act_grounding_pool_v1/act_grounding_annotations.jsonl `
  --split train `
  --output data/mvp_act_grounding_pool_v1/camera_control_train.v3.pending.jsonl

python -m idv_agent.scripts.prepare_camera_control_annotations validate `
  --input data/mvp_act_grounding_pool_v1/camera_control_train.v3.annotated.jsonl
```

当前 48/46 条只用于验证架构与接口，并不足以覆盖 search、目标获取、左右绕障、靠近与
Q 提示的组合。下一批必须按整 session split 独立扩充，不能从 validation session 借给
训练。
