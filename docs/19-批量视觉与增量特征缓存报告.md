## 一、批量视觉编码

### 目标

将原先逐帧调用视觉塔的路径改为按任务聚合、按 micro-batch 批量调用，降低 Python/CUDA kernel launch 开销，同时保留旧适配器兼容性。

### 实现

`Qwen3VLBackboneAdapter` 新增批量视觉路径：

- `_raw_visual_forward_batch(inputs)`：批量执行冻结视觉塔并 pooling；
- `_visual_forward_batch(inputs)`：raw pooling 后应用 `visual_projection`；
- `encode_frames(images, task_cache, micro_batch_size)`：批量图像编码和条件融合。

`train_vla.encode_batch()` 新增 `vision_micro_batch_size`，默认值为 8。它按 `(instruction, mode_id)` 分组，将未命中缓存的帧分块送入 `encode_frames()`；如果适配器没有该接口，则回退到逐张 `encode_frame()`。

CLI：

```bash
python -m idv_agent.scripts.train_vla ... --vision-micro-batch-size 8
```

## 二、冻结 raw feature 缓存

### 缓存点

持久缓存不再保存包含可训练层的最终 feature，而只保存：

```text
Qwen vision output → mean(dim=1) → raw feature
```

规范名为 `mean_dim1_v1`。训练查表后重新执行当前 `visual_projection` 和 `condition_projection`，因此跨 batch/epoch 不会使用 stale 投影，也不会切断可训练层梯度。

### 精确一致性

`encode_raw_frames()` 使用 `eval()` + `torch.inference_mode()`；`project_raw_features()` 对查表结果重新接入 autograd。测试验证实时路径和查表路径使用相同 pooling、投影和条件融合，采用 `torch.equal` 逐元素比较，要求 loss 差异为 0，而不是近似相等。

### 增量磁盘格式

新增 [raw_feature_cache.py](../idv_agent/training/raw_feature_cache.py)：

```text
cache_dir/
  index.json        # schema、pooling、raw_dim、dtype、path→shard/offset
  stats.json
  shard_<session>_00000.pt
  shard_<session>_00001.pt
```

`RawFeatureCache` 特性：

- key 为规范化绝对图片路径；instruction/mode 不参与 raw 身份；
- 每个 session 追加独立 shard；已有 shard 不重写；
- 新运行只编码 index 中不存在的路径；
- shard 首次读取后驻留内存，避免每帧重复 `torch.load`；
- index 通过临时文件 + `os.replace` 原子更新。

### 预编码命令

新增 [precompute_vla_features.py](../idv_agent/scripts/precompute_vla_features.py)：

```bash
python -m idv_agent.scripts.precompute_vla_features \
  --data data/vla_raw_sessions/.../vla_chunks_v4.jsonl \
  --model-path /models/Qwen3-VL-4B-Instruct \
  --output cache/qwen_raw_v1 \
  --device cuda \
  --micro-batch-size 8
```

脚本输出 `unique_frames`、`new_frames_encoded`、shard 数、raw 维度、dtype 和 pooling 版本。后续录制新 session 时重复执行同一命令即可增量追加。

## 三、训练集统计

对当前仓库全部 `vla_chunks_v4.jsonl` 的离线统计：

| 指标 | 数值 |
|---|---:|
| chunk 文件 | 129 |
| chunk 样本 | 26,402 |
| 帧引用 | 211,216 |
| 唯一图片帧 | 27,305 |
| 重复率 | 87.07% |
| FP16 × 2560 raw feature | 约 133.3 MiB |

视觉塔 forward 数量理论上从 211,216 降至 27,305，约减少 7.74 倍。端到端训练还包含投影、时序网络、head、反向传播和数据搬运，实际加速应以云 GPU 实测为准。

## 四、训练接入

```bash
python -m idv_agent.scripts.train_vla \
  --data data/.../vla_chunks_v4.jsonl \
  --init-checkpoint checkpoints/M2_VG \
  --raw-feature-cache cache/qwen_raw_v1 \
  --vision-micro-batch-size 8
```

启用 raw cache 后：

- 命中时跳过图片读取和 Qwen 视觉塔；
- 当前投影层仍参与梯度计算；
- 训练 manifest 记录 `vision_micro_batch_size`；
- 评估和 slow-accuracy pass 也可复用同一 raw cache。

## 六、当前限制

1. 预编码脚本需要可用 Qwen 权重和正确的 Transformers 运行时；当前开发终端的 CPU-only Torch 不能代表云 GPU 运行环境。
2. raw cache manifest 当前记录模型/池化基础字段；若更换模型权重、processor 或图像预处理，应使用新缓存目录，不能混用旧 shard。
3. `evaluate_vla.py` 的独立 CLI 尚未增加 `--raw-feature-cache` 参数；训练主流程及其内部评估已支持传递 raw cache，独立评估命令仍使用原有最终 feature cache 路径。
